이 문서는 빌더 10개 그룹(G1~G10)이 **그대로 따라 만드는** 단일 기획서다. 빌더는 질문할 수 없다. 여기 적힌 값(색, 폰트, 문구, 수치)은 임의로 바꾸지 않는다. 문서에 없는 세부는 각 브리프의 "컨셉 한 줄"과 0장의 원칙에 맞춰 스스로 결정한다.

## 0. 공통 원칙 요약

1. **정적 사이트, 빌드 단계 없음.** HTML/CSS/JS만. 라이브러리는 `studio/assets/vendor/` 안의 로컬 파일만(GSAP 3.15 전 플러그인, Lenis, Three.js r186 ES module). 외부 스크립트 CDN 금지. 폰트만 Google Fonts `<link>`.
2. **외부 이미지 0장.** 모든 그림은 코드로 만든다(inline SVG, CSS, Canvas 2D, WebGL, 타이포).
3. **한국어, 모바일 390px 완벽, 데스크톱 1440px.** 가로 스크롤 없음, 좌우 여백 최소 16px(권장 20px).
4. **첫 화면은 로드 후 1.2초 안에 핵심 내용(브랜드명, 헤드라인, CTA)이 보여야 한다.** JS 실패나 `prefers-reduced-motion`에서도 중요한 내용이 숨겨진 채 남으면 안 된다.
5. **목업은 가상 브랜드.** 실존 회사·로고·인물 모방 금지. 스튜디오 홈페이지는 실제 사업이므로 **지어낸 숫자, 고객 수, 수상, 평점, 후기 금지.**
6. **안티 슬롭 규칙**(frontend-design, gemini-frontend-design 스킬): 크림+테라코타 기본값 금지, 다크 슬레이트+네온 퍼플 금지, 제목마다 아이브로(작은 대문자 라벨) 금지, 실제 순서가 아닌 01/02 번호 금지, 장식용 알약 배지 금지, 카드 안 카드 금지, 50/50 히어로 템플릿 금지, 똑같은 둥근 카드 그리드 금지, 페이지당 폰트 패밀리 최대 2개, 섹션당 주요 CTA 1개, 생성한 한국어 문구에 엠대시(—) 금지, 버튼 문구 끝 화살표(→) 금지, `transition: all` 금지, 대기 상태에서 까딱거리는 무한 루프 금지.
7. **모션 원칙**(emil-design-eng, better-motion): UI 전환 140~240ms, 입장 300~600ms, ease-out 계열(`cubic-bezier(0.22, 1, 0.36, 1)`), `transform`/`opacity`/`clip-path`만 애니메이션, 누름 상태 `scale(0.97)`, `scale(0)`에서 시작 금지(최소 0.9), 호버 효과는 `@media (hover: hover) and (pointer: fine)` 안에서만. 한 페이지에 "큰 연출"은 하나(시그니처 효과), 나머지는 조용하게.
8. **썸네일 규칙:** 각 목업의 첫 화면(1440×900, 로드 후 약 2.5초 시점)이 포트폴리오 썸네일이 된다. 프리로더, 전체 화면 인트로, 쿠키 배너 금지. URL에 `?shot=1`이 있으면 인트로 애니메이션을 건너뛰고 "가장 보기 좋은 정지 장면"을 즉시 그린다(각 브리프에 명시). `?shot=1`일 때 컨셉 배지는 숨긴다.

## 1. 스튜디오 브랜드

### 1.1 이름과 포지셔닝

- **이름:** 첫화면 스튜디오
- **라틴 표기(보조):** First Screen Studio (푸터, `<title>`, 메타에만 사용. 로고에는 쓰지 않는다)
- **한 줄 포지셔닝:** "손님이 머물지 떠날지 정하는 첫 화면부터, 문의 버튼까지 책임지는 홈페이지 제작 스튜디오."
- **이름의 근거:** 방문자는 홈페이지의 첫 화면에서 판단한다. 스튜디오의 약속(첫 화면을 제대로 만든다), 포트폴리오의 형식(16개의 첫 화면), 패키지 이름(첫 화면 / 다섯 화면 / 열 화면 / 맞춤 화면)이 전부 한 단어에서 나온다.

### 1.2 말투

- 사장님에게 말하는 **차분한 존댓말**("~합니다", "~드립니다"). 과장 부사("최고의", "압도적인", "혁신적인") 금지.
- 숫자는 **우리가 지킬 수 있는 약속**에만 쓴다(가격, 기간, 수정 횟수, 회신 시간). 성과 수치는 쓰지 않는다.
- 전문 용어는 풀어서 쓴다. "반응형" 대신 "휴대폰에서도 잘 보이게", 필요한 경우 괄호로 병기.
- 문장은 짧게. 한 문장에 약속 하나.
- 버튼은 눌렀을 때 일어나는 일을 그대로 쓴다("무료 상담 신청하기", "의뢰서 보내기").

### 1.3 로고 / 워드마크 (SVG + 타입)

- 워드마크: **"첫화면"** 세 글자, Hahmlet 800, 자간 -0.02em.
- 심벌: 글자를 감싸는 **뷰포트 모서리 표시** 두 개. 왼쪽 위 `⌜`, 오른쪽 아래 `⌟` 모양의 L자 선(굵기는 글자 가로획과 같게, 길이는 글자 높이의 38%, 끝은 직각). inline SVG `<path>` 2개로 그린다. 글자와 모서리 사이 간격은 글자 높이의 18%.
- 헤더에서는 높이 28px(모바일 24px). 색은 `--ink`. 호버 시 두 모서리가 바깥으로 3px 벌어진다(180ms ease-out).
- 파비콘: 32×32 SVG data URI. `--cobalt` 배경의 둥근 사각형(반경 7) 위에 흰색 모서리 표시 두 개와 가운데 `--marker` 점 하나.
- 푸터에는 워드마크 뒤에 "스튜디오"를 IBM Plex Sans KR 500으로 붙인다.

### 1.4 컬러 토큰 (의도적인 단일 라이트 테마)

**다크 모드를 만들지 않는다.** 이유: 이 페이지의 주인공은 색이 제각각인 16개의 썸네일이다. 갤러리 벽처럼 배경이 한 가지로 고정되어야 썸네일끼리 비교가 되고, 테마 전환은 그 일관성을 깬다. 대신 가격 섹션과 푸터만 잉크색 밴드로 뒤집어 리듬을 준다.

| 토큰 | 이름 | HEX | 용도 |
|---|---|---|---|
| `--paper` | 종이 | `#F4F5F0` | 페이지 배경 |
| `--surface` | 백 | `#FFFFFF` | 입력 필드, 스테이지 프레임, 표 배경 |
| `--ink` | 쪽먹 | `#0F1A3A` | 본문·제목 글자, 가격 섹션과 푸터 배경 |
| `--cobalt` | 코발트 | `#2746F5` | 주요 버튼, 링크, 선택 상태 (흰 글자 대비 6.4:1) |
| `--marker` | 형광펜 | `#F4E84A` | 뷰포트 모서리 표시, 포커스 링 보조, 잉크 배경 위 강조 (글자색으로는 잉크 배경에서만) |
| `--mist` | 안개 | `#5B6478` | 보조 글자 (종이 위 대비 5.4:1) |
| `--line` | 선 | `#D9DCE3` | 1px 구분선, 테두리 |
| `--ink-soft` | 옅은 먹 | `#C9D0E6` | 잉크 배경 위 보조 글자 (대비 9:1 이상) |
| `--danger` | 경고 | `#C4281C` | 폼 오류 전용 |

규칙: 코발트는 "누를 수 있는 것"에만 쓴다. 형광펜은 "지금 보고 있는 것/선택된 것"에만 쓴다. 그 외 장식 색 금지. 그라디언트 금지(히어로 스테이지 그림자 제외). 그림자는 중립색 다층 그림자만: `0 1px 1px rgba(15,26,58,.04), 0 4px 8px rgba(15,26,58,.05), 0 16px 32px rgba(15,26,58,.07)` (스테이지와 플로팅 CTA에만).

### 1.5 타이포그래피

- **Hahmlet** (700, 800): 디스플레이, h1, h2, 가격 숫자, 로고. 붓끝이 살아 있는 명조 계열이라 "만든 사람의 손"이 보인다.
- **IBM Plex Sans KR** (400, 500, 600): 본문, UI, 폼, 표.
- Google Fonts: `family=Hahmlet:wght@700;800&family=IBM+Plex+Sans+KR:wght@400;500;600&display=swap`, `preconnect` 2개 포함.
- 스케일(5단계만 사용):
  - display: `clamp(2.75rem, 8.2vw, 8rem)` / Hahmlet 800 / 행간 1.04 / 자간 -0.03em
  - h2: `clamp(1.875rem, 4.2vw, 3.5rem)` / Hahmlet 700 / 행간 1.18 / 자간 -0.02em
  - title: `1.375rem`(22px) / Hahmlet 700 / 행간 1.35 (패키지명, 절차 단계 제목, FAQ 질문)
  - body: `1.0625rem`(17px, 모바일 16px) / Plex 400 / 행간 1.7
  - small: `0.875rem`(14px) / Plex 400~500 / 행간 1.6 (첫 화면 위쪽에서는 14px 미만 금지)
- 숫자는 `font-variant-numeric: tabular-nums`. 모노스페이스 폰트 추가 금지.
- 한국어 줄바꿈: 전역 `word-break: keep-all; overflow-wrap: anywhere; line-break: strict;`, 제목에는 `text-wrap: balance`, 본문 문단 최대 폭 `36em`.

### 1.6 시그니처 모티프: 뷰포트 모서리

로고의 L자 모서리 표시가 페이지 전체의 "선택 틀"이 된다.
- 포트폴리오 썸네일 호버/포커스: 네 모서리에 `--marker`(종이 위에서는 `--ink`) L자 표시가 안쪽 8px에서 바깥 6px로 벌어지며 나타난다(200ms).
- 폼 필드 포커스: 테두리 2px `--cobalt` + 왼쪽 위/오른쪽 아래 모서리 표시.
- 가격표에서 권장 패키지 열: 모서리 표시로만 구분(배지 금지).
- 섹션 구분: 섹션 제목 왼쪽 위에 작은 모서리 표시 하나(크기 14px). 아이브로 라벨 대신 이것만 쓴다.
구현: 공통 클래스 `.corners`(의사요소 2개 + 추가 span 2개 또는 SVG 4개), CSS 변수 `--corner-gap`으로 벌어짐 제어.

### 1.7 히어로의 단 하나의 큰 효과: "블라인드 스테이지"

**무엇이 그려지는가.** 히어로 헤드라인 아래에 화면 폭의 대부분을 차지하는 16:10 **뷰포트 프레임**(스테이지)이 있다. 그 안에는 16개 목업의 실제 첫 화면 썸네일이 한 장씩 보인다. 프레임 상단에는 높이 40px의 얇은 주소 표시줄이 있다: 왼쪽에 모서리 심벌과 현재 시안의 가상 주소(`ongi-bakery.kr` 형태로 `<slug>.kr`), 오른쪽에 `03 / 16` 순번(실제 순서이므로 번호 사용 허용)과 "자동 넘김 멈춤/재생" 버튼. 프레임 아래 캡션 줄: "지금 보이는 화면: **온기 베이커리**, 베이커리 카페" + 이전/다음 버튼(44×44).

**어떻게 움직이는가.** 썸네일은 가로 **슬랫(블라인드 살) 10개**(모바일 6개)로 잘려 있다. 각 슬랫은 앞면=현재 썸네일의 해당 띠, 뒷면=다음 썸네일의 해당 띠(`background-image` + `background-size: 100% (슬랫수×100%)` + 슬랫별 `background-position`). 표시 순서는 2.3의 표 순서(1번 해온 시스템즈가 첫 장). 전환 시 각 슬랫이 `rotateX(0 → -180deg)`로 뒤집힌다(슬랫 컨테이너 `perspective: 1400px`, `backface-visibility: hidden`, 0.7s, `power3.inOut`). 스태거 0.045s, 순서는 **포인터가 마지막으로 있던 세로 위치에서 가까운 슬랫부터**(포인터 기록이 없으면 위에서 아래). 전환이 끝나면 앞면 이미지를 다음 것으로 바꾸고 회전을 0으로 즉시 되돌린다. 전환 직전에 다음 이미지를 `Image()`로 미리 디코드한다. 주소 표시줄의 주소는 ScrambleTextPlugin으로 0.5s 동안 바뀐다.

**자동 진행.** 4.2초마다 다음 장. 다음 경우 멈춘다: 스테이지에 호버/포커스, 화면 밖(IntersectionObserver), 탭 비활성(`visibilitychange`), 사용자가 멈춤 버튼을 누름(이 경우 다시 누를 때까지 유지). 사용자가 이전/다음을 누르면 자동 진행 타이머를 리셋한다.

**포인터 반응(데스크톱, fine pointer만).** 스테이지 위에서 포인터 근처 슬랫이 살짝 들린다: 포인터 Y와의 거리로 가우시안 감쇠를 주어 최대 `rotateX(-9deg)`, `gsap.quickTo` 0.35s. 블라인드를 손가락으로 벌리는 느낌이다. 스테이지 전체는 현재 목업으로 가는 링크(`<a>`)이며, 클릭하면 `work/<slug>/`로 이동한다.

**스크롤 반응.** 페이지 최상단에서 스테이지는 `scale(0.94)`, 스크롤 0 → 히어로 높이의 35% 구간에서 `scale(1)`로 스크럽(ScrollTrigger, scrub 0.4). 헤드라인은 같은 구간에서 `translateY(-24px)`까지만 움직인다(투명도 변화 없음).

**모바일.** 슬랫 6개, 들림 효과 없음. 좌우 스와이프(GSAP Observer, `tolerance: 40`, 세로 스크롤 유지 `lockAxis`)로 이전/다음. 탭하면 목업으로 이동. 자동 진행 동일. 스테이지 폭은 `100% - 32px`, 모서리 반경 10px.

**reduced-motion.** 자동 진행 끔, 뒤집기 없음. 이전/다음 버튼을 누르면 150ms 투명도 교차 전환만. 스크롤 스크럽 없음(스테이지는 처음부터 `scale(1)`).

**JS 실패/썸네일 없음 대비.** HTML에는 스테이지 안에 첫 번째 시안의 `<img>`(eager, `fetchpriority="high"`, width/height 지정)와 캡션이 정적으로 들어 있다. 각 슬라이드 데이터에는 대표색이 있고, 이미지 로드 실패 시(`onerror`) 그 슬라이드는 대표색 배경 + 가운데 브랜드명(Hahmlet 800, 대표색과 대비되는 글자색)으로 그린다. 빌드 시점에는 썸네일이 없으므로 **이 대체 화면으로도 히어로가 완성되어 보여야 한다.**

**로드 시퀀스.** 헤드라인과 버튼은 CSS만으로 즉시 보인다. `document.fonts.ready`(최대 800ms 대기) 후 헤드라인 줄 단위 마스크 리빌(SplitText lines, `yPercent: 100 → 0`, 0.7s, 스태거 0.08)과 스테이지 `y: 40 → 0, opacity: 0.6 → 1`(0.8s). 전부 `gsap.from()`으로만 구현해서 GSAP이 없으면 그냥 보인다.

## 2. 스튜디오 홈페이지 스펙 (`studio/index.html`)

### 2.0 파일과 설정

```
studio/index.html
studio/assets/css/studio.css
studio/assets/js/config.js      (일반 스크립트. window.STUDIO_CONFIG 정의)
```

`config.js` 스키마(이 키 이름 그대로. 목업의 컨셉 배지도 이 파일을 읽는다):

HTML에는 같은 값을 **정적 기본값으로 미리 써 두고**, `studio.js`가 `[data-config="email"]` 같은 속성을 찾아 config 값으로 덮어쓴다(JS 실패 시에도 내용이 보이도록). **가격은 `index.html`의 `#pricing` 섹션 한 곳에만 쓴다.** 섹션 맨 위에 `<!-- ★ 가격 수정은 이 섹션에서만 합니다 -->` 주석을 두고, 폼이나 다른 곳에서 가격이 필요하면 `[data-price]` 속성에서 읽는다. 다른 섹션 문구에 금액을 직접 쓰지 않는다.

**동의(필수).** 제출 버튼 바로 위, 항상 펼쳐진 고지 상자(`--paper` 배경, small 글자, 표 형태 3행):

- `수집 항목` : `성함(상호), 연락처, 이메일(입력하신 경우), 문의 내용`
- `수집 목적` : `홈페이지 제작 상담과 견적 안내`
- `보유 기간` : `상담 종료 후 1년간 보관한 뒤 파기합니다. 계약을 맺으시면 관련 법령이 정한 기간 동안 보관합니다.`
- 아래 한 줄: `동의하지 않으실 수 있으며, 그 경우 상담 신청이 어렵습니다.`
- 체크박스(`consent`, 필수) 라벨: `[필수] 개인정보 수집·이용에 동의합니다.` 오류: `상담을 위해 개인정보 수집·이용 동의가 필요합니다.`

**제출 버튼.** `의뢰서 보내기`(코발트, 전체 폭, 높이 56px). 전송 중: `보내는 중…` + `disabled` + `aria-busy`. 버튼 아래 small: `보내신 내용은 상담 목적으로만 사용합니다.`

**검증 동작.** `novalidate` + JS 검증. 필드 blur 시 그 필드만 검증, 제출 시 전체 검증 후 첫 오류 필드로 포커스 이동(스크롤 포함). 오류는 필드 아래 small `--danger` 텍스트 + 필드 테두리 `--danger` + `aria-invalid="true"` + `aria-describedby`. 폼 위에 `role="alert"` 요약 `확인이 필요한 항목이 2개 있습니다.` 입력을 고치면 그 필드 오류 즉시 제거. JS가 없으면 기본 HTML 검증(`required`)이 동작하도록 `required` 속성도 넣어 두고 JS가 `novalidate`를 붙인다. `alert()` 금지.

**전송 로직.**
1. 값을 모아 JSON 구성: `{ name, phone, email, replyBy, industry, package, budget, timeline, likedWorks: [], reference, features: [], materials, message, consent: true, consentAt: ISO시각, submittedAt: ISO시각, page: location.href }`.
2. `STUDIO_CONFIG.FORM_ENDPOINT`가 있으면 `fetch(POST, headers: {"Content-Type":"application/json","Accept":"application/json"}, body)` (AbortController 10초).
   - 성공(2xx): 성공 화면 A.
   - 실패/시간 초과: 폼 위 `role="alert"`: `전송에 실패했습니다. 아래 의뢰서를 복사해 이메일이나 카카오톡으로 보내 주시면 바로 확인하겠습니다.` 그리고 성공 화면 B(제목만 `의뢰서를 직접 보내 주세요`로 교체)를 보여준다.
3. 엔드포인트가 없으면: 성공 화면 B.

**성공 화면.** 폼 면 안에서 폼을 숨기고 같은 자리에 표시(높이 전환 300ms, 내용 페이드 200ms). 제목(`tabindex="-1"`)으로 포커스 이동, 컨테이너 `aria-live="polite"`. 섹션 상단이 보이도록 스크롤.
- **A (전송 성공):** 제목 `의뢰서를 잘 받았습니다` / 본문 `영업일 기준 24시간 안에 {답변 방법}(으)로 연락드리겠습니다. 급하시면 아래 연락처로 바로 말씀해 주세요.` / 접수 내용 요약 상자 / 버튼 `접수 내용 복사하기` / 연락처 줄.
- **B (엔드포인트 없음 또는 전송 실패):** 제목 `의뢰서가 완성되었습니다. 아래 내용을 보내 주세요` / 본문 `아직 자동 접수가 연결되어 있지 않습니다. 아래 의뢰서를 복사해서 이메일이나 카카오톡으로 보내 주시면 바로 확인하겠습니다.` ("접수되었습니다"라고 쓰지 않는다. 보내지지 않았기 때문이다.) / 요약 상자(`<pre>` 스타일, `user-select: all`, 스크롤 없이 전체 표시) / 주 버튼 `의뢰서 복사하기`(누르면 1.6초간 `복사했습니다`로 바뀜, `navigator.clipboard` 실패 시 텍스트 전체 선택 + `길게 눌러 복사해 주세요` 안내) / `보낼 곳` 아래 이메일 주소(선택 가능한 큰 텍스트 + 작은 `주소 복사` 버튼) / 카카오톡 버튼(설정된 경우) / 텍스트 버튼 `내용 고치기`(폼으로 돌아감, 입력값 유지).
- 성공 화면에 색종이 등 축하 효과 금지. 요약 상자 네 모서리에 뷰포트 모서리 표시가 한 번 그려지는 것(0.5s)이 유일한 연출.

입력값은 `sessionStorage`에 임시 저장(새로고침 대비, try/catch로 감쌈, 성공 화면 A 이후 삭제).

## 3. 목업 16종 브리프

### 3.0 브리프 읽는 법과 공통 사항

- 각 목업은 `studio/work/<slug>/index.html` + `style.css` + `main.js`(필요하면 모듈 추가)로 된 **한 페이지짜리 긴 사이트**다. "패키지"는 그 시안이 어느 상품의 견본인지 나타내는 표시일 뿐, 실제로 여러 페이지를 만들지 않는다. 내부 메뉴는 같은 페이지의 앵커로 연결한다.
- 팔레트, 폰트, 헤드라인, CTA 문구는 **그대로** 쓴다. "섹션" 항목의 문구는 핵심만 적었다. 나머지 본문(메뉴 설명, 가격, 가상의 후기 등)은 같은 말투로 빌더가 채운다. 가상의 가격, 후기, 숫자는 목업 안에서 허용된다. 전화번호는 `02-000-0000`, 주소는 `서울 OO구 가상로 12` 같은 명백한 가상 값만 쓴다.
- 목업 안의 폼과 예약 버튼은 실제 전송하지 않는다. 제출하면 같은 자리에 `컨셉 시안이라 실제로 접수되지는 않습니다.`가 포함된 확인 문구를 보여준다.

- **브랜드:** 달무리 / DALMURI. 예약제 한식 다이닝 바.
- **업종/카테고리:** 한식 다이닝 바 / 매장·식음. **대상:** 기념일, 접대 자리를 찾는 30~50대. **패키지:** 다섯 화면.
- **컨셉 한 줄:** "먹물이 번져 달무리가 되는 밤. 세로로 흐르는 글과 여백으로 코스의 호흡을 보여준다."
- **팔레트:** 칠흑 `#0C0C0E`, 숯 `#1E1E22`, 한지 `#E9E3D5`, 놋쇠 `#B9975B`, 달빛 `#F4F1E8`, 홍시 `#C4472D`(예약 마감 표시 한두 곳만).
- **폰트:** Song Myung 400 (제목, 세로쓰기), Gowun Batang 400/700 (본문).
- **분위기:** 정적, 여백, 먹, 느린 호흡.
- **레이아웃:** 헤드라인은 화면 오른쪽 1/3에 **세로쓰기**(`writing-mode: vertical-rl`), 왼쪽 2/3은 달무리. 내비는 최소(로고, `예약`). 섹션은 넓은 여백과 비대칭 열. 데스크톱의 코스 목록은 오른쪽에서 왼쪽으로 읽는 세로 열, 모바일은 일반 가로 목록.
- **히어로 문구:** h1(세로) `달이 번지는 밤, 한 상의 여백` / 보조(가로, 작게) `제철 재료로 짓는 아홉 접시. 하루 두 번, 열두 분만 모십니다.` / CTA `자리 예약하기`
- **시그니처 효과 (순수 WebGL 프래그먼트 셰이더, three 없이):** 전체 화면 쿼드. 도메인 워핑 fbm(5옥타브): `ink = fbm(p + 2.0 * fbm(p + t * 0.03))`. 고리 SDF: `ring = smoothstep(w, 0.0, abs(length(p - c) - R))`, R은 로드 후 1.6초 동안 0 → 0.32로 열린다. 최종색 = `mix(칠흑, 달빛, ring * (0.55 + 0.45 * ink))` + 고리 바깥에 놋쇠색 옅은 번짐 + 고리 안쪽 원판 6% 밝게(달). CSS로 6% 필름 그레인(SVG feTurbulence data URI) 덧씌움.
  - 포인터: 포인터 근처에서 p를 `0.08 * exp(-d² * 8)`만큼 밀어 먹이 끌려간다(유니폼 lerp).
  - 스크롤: 히어로를 벗어나며 R이 커지고 고리가 먹 속으로 풀린다.
  - 모바일: DPR 1.25, 4옥타브, 포인터 대신 느린 자동 표류.
  - reduced-motion: `t = 8초` 한 프레임. 대체: CSS 방사형 그라디언트로 만든 정적 고리.
  - 로드 1초 시점에 고리가 60% 열려 있어야 한다. `?shot=1`: 고리 완전히 열린 `t = 8초`.
- **보조 인터랙션:** (1) 코스: 접시를 위에서 본 SVG(원 접시 + 붓질 같은 음식 형태, feTurbulence 변위로 붓 질감)가 코스마다 MorphSVGPlugin으로 변한다. 코스 이름은 SplitText 글자 단위로 세로 마스크 리빌. (2) 예약 달력: 날짜를 **달의 위상**으로 표시(가능한 날은 밝게). 날짜 → 시간(18:00 / 20:30) → 인원 → 확인(데모). 키보드 화살표 이동. (3) 전통주 목록: 호버 시 놋쇠 밑줄이 오른쪽에서 그려지고 옆에 설명이 나타난다.
- **섹션:** 히어로 / 철학 h2 `덜어낼수록 선명해지는 맛` / 코스 h2 `가을, 아홉 접시` (가을 코스 148,000원, 전통주 페어링 68,000원) / 전통주 h2 `잔에 따르는 계절` / 공간 h2 `열두 자리의 바` (바 카운터와 좌석 12개의 SVG 선화) / 예약 h2 `자리를 맡아 두겠습니다` / 오시는 길.
- **이미지 계획:** 셰이더, SVG 접시 5형태, 달 위상 SVG, 바 평면 선화.
- **모바일 메모:** 세로 헤드라인 유지(2열, 높이 60svh), 고리는 위쪽 가운데. 코스는 세로 스택.
- **규칙 예외:** 다크 + 금속색 조합은 고급 다이닝의 흔한 공식이지만 여기서는 "먹과 놋그릇"이라는 소재에서 나온 선택이고, 세로쓰기와 셰이더로 차별화한다.
- **중요 스킬:** frontend-design(절제), gsap-plugins(MorphSVG, SplitText), better-motion.

- **보조 인터랙션:** (1) `한 문장 써 보세요`: textarea 입력이 원고지 칸에 실시간으로 옮겨진다(최대 60자, `23 / 60자`). 입력을 멈추면 빨간 펜 칭찬 메모가 달린다(데모, `잘 썼어요!` 등 4종). (2) 시간표 탭(중1~고3): 손으로 그린 듯한 밑줄 표시가 선택 탭으로 미끄러진다. (3) 첨삭 전후: 학생 문단 + `첨삭 보기` 토글 → 취소선이 그어지고 줄 사이에 고친 표현이 써진다.
- **섹션:** 히어로 / 수업 방식 h2 `읽고, 줄이고, 다시 씁니다` (읽기 → 요약 → 쓰기, 실제 순서라 번호 사용) / 첨삭 견본 h2 `빨간 펜이 지나간 자리` / 반 편성과 시간표 h2 `학년별 시간표` / 수강료 h2 `수강료` (표) / 선생님 h2 `첨삭하는 사람` (손글씨 서명 SVG) / 신청 h2 `레벨 테스트 신청서` (답안지 형식 폼).
- **이미지 계획:** 원고지 격자(CSS), 펜 표시 SVG path 20여 개, 펜촉 SVG, 서명 SVG.
- **모바일 메모:** 답안지는 화면 폭에서 좌우 12px만 남기고 꽉 차게(안쪽 패딩 16px 포함해 글 여백 16px 이상 확보). 원고지 칸은 정사각형 유지.
- **중요 스킬:** gsap-plugins(DrawSVG, MotionPath, TextPlugin), frontend-design, accessibility.

## 4. 빌더 공통 규칙

### 4.1 파일 규칙

```
studio/
  index.html                      (G9)
  assets/css/studio.css           (G9)
  assets/js/config.js             (G9가 작성. 다른 그룹은 읽기만)
  assets/js/studio.js             (G9)
  assets/thumbs/<slug>.jpg        (나중에 자동 생성. 빌더는 만들지 않는다)
  assets/vendor/gsap|lenis|three  (수정 금지)
  work/<slug>/index.html          (각 그룹)
  work/<slug>/style.css
  work/<slug>/main.js             (+ 필요 시 scene.js 등 모듈)
```

- 각 그룹은 **자기 폴더만** 만든다. 다른 그룹 폴더, vendor, config.js를 수정하지 않는다. 공유 CSS/JS 파일을 새로 만들지 않는다(컨셉 배지도 각 목업에 직접 넣는다. 4.2 참조).
- 경로는 전부 상대 경로. 목업에서 vendor는 `../../assets/vendor/...`, 설정은 `../../assets/js/config.js`.
- GSAP: `<script src="../../assets/vendor/gsap/gsap.min.js" defer>` 후 필요한 플러그인만 로드하고 `gsap.registerPlugin(...)`. 쓰지 않는 플러그인은 로드하지 않는다.
- Three.js: `<script type="module">`에서 `import * as THREE from '../../assets/vendor/three/three.module.min.js'`. (이 파일은 같은 폴더의 `three.core.min.js`를 불러온다. ES module이므로 `file://`이 아닌 로컬 서버로 확인한다: `python3 -m http.server`.) `examples/jsm` 애드온은 없다. OrbitControls, EffectComposer, 폰트 로더 없이 코어만으로 만든다.
- Lenis: 사용 허용 목업은 `supmeong-stay`, `teum-perfume`, `dalmuri`뿐. 데스크톱 fine pointer에서만 켜고 `lenis.on('scroll', ScrollTrigger.update)` + `gsap.ticker`로 연결, reduced-motion에서는 끈다. 나머지는 기본 스크롤. ScrollSmoother는 쓰지 않는다.
- `<head>` 필수: `<html lang="ko">`, `meta charset`, `meta viewport(width=device-width, initial-scale=1, viewport-fit=cover)`, `<title>{브랜드명} | 컨셉 시안 · 첫화면 스튜디오</title>`, `meta description`, 목업에는 `<meta name="robots" content="noindex">`(가상 업체가 검색에 실제처럼 노출되지 않게), SVG data URI 파비콘(브랜드색 원 또는 이니셜), Google Fonts `preconnect` 2줄 + 지정 패밀리와 굵기만 담은 `<link>`(`display=swap`).
- CSS: `:root`에 브리프의 팔레트를 토큰으로 선언. 모바일 우선, `min-width` 미디어 쿼리. 전역 `box-sizing: border-box`, `word-break: keep-all; overflow-wrap: anywhere;`, 제목 `text-wrap: balance`, `html { -webkit-text-size-adjust: 100% }`, `body { overflow-x: clip }`. 높이는 `svh/dvh` 사용(`100vh` 단독 금지).
- 페이지당 직접 작성한 JS는 가급적 60KB 이하, 주석은 "왜"만.

### 4.2 컨셉 배지 (모든 목업 공통, 각 목업에 직접 삽입)

모든 목업의 `<body>` 맨 끝(스크립트 앞)에 아래 구조를 넣는다. 스타일은 각 목업 `style.css` 끝에 그대로 복사한다. **모양은 목업의 디자인과 무관하게 동일**해야 한다(스튜디오의 서명이므로).

```html
<a class="concept-badge" href="../../index.html#work" aria-label="컨셉 시안입니다. 첫화면 스튜디오 포트폴리오로 돌아가기">
  <span class="concept-badge__mark" aria-hidden="true"></span>
  <span class="concept-badge__text">컨셉 시안 · <span data-studio-name>첫화면 스튜디오</span></span>
</a>
<script src="../../assets/js/config.js"></script>
<script>
  (function () {
    var c = window.STUDIO_CONFIG, el = document.querySelector('[data-studio-name]');
    if (c && c.name && el) el.textContent = c.name;
    if (/[?&]shot=1/.test(location.search)) document.documentElement.classList.add('is-shot');
  })();
</script>
```

스펙:
- 위치: `position: fixed; left: 16px; bottom: calc(16px + env(safe-area-inset-bottom)); z-index: 2147483000`. 목업에 하단 고정 바가 있으면 `bottom`을 그 높이만큼 올린다. 왼쪽 아래에 목업의 고정 요소(카운터 등)가 있으면 그 요소를 배지 위로 옮긴다.
- 모양: 높이 36px, 좌우 패딩 12px, 반경 999px, 배경 `rgba(15, 26, 58, 0.92)`(스튜디오 잉크), 글자 `#FFFFFF`, 13px/500, `font-family: system-ui, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`(목업 폰트 수에 영향 주지 않게 시스템 폰트), `letter-spacing: 0`, `text-decoration: none`, `backdrop-filter: blur(8px)`, 테두리 `1px solid rgba(255,255,255,.18)`, 그림자 `0 2px 8px rgba(0,0,0,.18)`.
- `__mark`: 10×10px, 왼쪽 위 L자 모서리 표시(2px, `#F4E84A`), 텍스트와 간격 8px. CSS `border-left` + `border-top`으로 그린다.
- 상태: 호버 시 배경 불투명도 1 + 모서리 표시가 2px 바깥으로(150ms). `:focus-visible`은 `outline: 2px solid #F4E84A; outline-offset: 2px`. 누름 `scale(0.97)`.
- 모바일(<480px): 문구는 그대로 한 줄. 최대 폭 `calc(100vw - 32px)`.
- `html.is-shot .concept-badge { display: none }`.
- 가운뎃점은 이 배지의 고정 문구에만 쓰는 예외다.
- 인쇄 시 숨김.

### 4.3 애니메이션 안전 규칙

1. **CSS에서 콘텐츠를 숨기지 않는다.** `opacity: 0`, `visibility: hidden`, 화면 밖 `transform`을 스타일시트의 기본 상태로 쓰지 않는다. 숨긴 시작 상태는 오직 `gsap.from()` / `gsap.fromTo()`가 실행 시점에 만든다. GSAP 로드에 실패하면 모든 것이 그냥 보인다.
2. 스크립트 진입부를 `try/catch`로 감싸고, 실패 시 `document.documentElement.classList.add('no-motion')` 후 정적 상태로 둔다. 캔버스/WebGL 초기화 실패 시 브리프의 "대체" 화면이 보여야 한다(대체 화면은 캔버스 **뒤에 항상 존재**하고 캔버스가 준비되면 덮는 방식).
3. `gsap.matchMedia()`로 분기: `(prefers-reduced-motion: reduce)`, `(min-width: 768px)`, `(hover: hover) and (pointer: fine)`. reduced-motion에서는 pin, scrub, 자동 재생 루프, 시차를 끄고 브리프의 정지 상태를 보여준다. 색 변화와 150ms 이하 교차 페이드는 유지해도 된다.
4. 히어로: 브랜드명, 헤드라인, CTA는 **첫 페인트부터 보이거나 로드 후 1.2초 안에** 완전히 보여야 한다. 인트로 총 길이 2.5초 이하. 폰트 대기는 `document.fonts.ready`와 800ms 타임아웃 중 먼저 오는 쪽.
5. 스크롤 입장 애니메이션은 페이지당 3~5곳의 "의미 있는 순간"에만. 모든 섹션에 같은 페이드업을 붙이지 않는다. 한 번 재생(`once: true`)을 기본으로 한다.
6. ScrollTrigger: pin 구간은 데스크톱 600vh, 모바일 400vh를 넘지 않는다. 가로 pin 스크롤은 모바일에서 기본 가로 스냅 스크롤 또는 세로 스택으로 바꾼다. 폰트 로드와 이미지/캔버스 크기 확정 후 `ScrollTrigger.refresh()`. 리사이즈 시 pin 깨짐을 확인한다.
7. 값: 호버/누름 120~200ms, 패널·아코디언 240~320ms, 입장 400~700ms. 이징은 `power3.out` 또는 `cubic-bezier(0.22, 1, 0.36, 1)`. 닫힘은 열림보다 짧게. 바운스는 장난스러운 목업(ongi, kkoribyeol, heavy-club)에서만.
8. `transform`, `opacity`, `clip-path`, `filter`(작은 요소만)만 애니메이션. `width/height/top/left` 애니메이션 금지(높이 전환은 `grid-template-rows` 또는 측정 후 `height` 한 번). `will-change`는 움직이는 동안만.
9. 자동으로 5초 이상 움직이는 것에는 멈춤 수단이 있어야 한다(화면 밖 자동 정지 + 캐러셀류는 멈춤 버튼). 초당 3회 이상 깜박이는 것 금지. 소리는 반드시 사용자가 켠다.
10. `?shot=1`: 인트로 생략, 브리프에 적힌 정지 장면, 난수 시드 고정, 컨셉 배지 숨김.

### 4.4 성능 예산

- 캔버스/WebGL: `devicePixelRatio`는 최대 2(전체 화면 셰이더와 모바일은 1.5 이하). IntersectionObserver로 **화면 밖이면 루프 정지**, `visibilitychange`로 탭 비활성 시 정지. `requestAnimationFrame` 하나로 통합. 리사이즈는 150ms 디바운스.
- 60fps 목표(중급 휴대폰 30fps 이상). 프레임당 객체 생성 금지, 배열 재사용.
- Three.js: 그림자 맵 금지, 드로콜 80 이하, InstancedMesh와 지오메트리 병합, 텍스처는 캔버스 생성 1024px 이하, 정리 시 `dispose`.
- SVG 필터(`feTurbulence` 등)의 속성을 프레임마다 애니메이션하지 않는다.
- 폰트: 패밀리 최대 2개, 굵기 합계 5개 이하(브리프 지정값만).
- 첫 화면 레이아웃 이동(CLS) 없음: 캔버스와 미디어 영역에 `aspect-ratio` 또는 고정 높이.
- 스크롤/포인터 리스너는 `passive: true`, 포인터 좌표는 rAF에서 한 번만 읽어 쓴다.

### 4.5 접근성 체크리스트

- 랜드마크: `header`, `nav`, `main`, `footer`. h1은 하나, 제목 단계 건너뛰지 않기.
- 모든 인터랙션은 키보드로 가능. 커스텀 컨트롤에 역할과 상태(`role="slider"`, `aria-pressed`, `aria-expanded`, `aria-selected`, `role="switch"`). 드래그 전용 기능에는 버튼 또는 키보드 대안.
- `:focus-visible` 포커스 링: 2px 이상, 배경과 3:1 이상 대비, `outline-offset: 2px`. `outline: none`만 쓰는 것 금지.
- 글자 대비: 본문 4.5:1, 큰 글자(24px 이상 또는 19px 굵게)와 UI 3:1. 브리프의 "글자 규칙"을 지킨다. 캔버스/풍경 위 글자는 스크림으로 보장한다.
- 장식 캔버스와 SVG는 `aria-hidden="true"`. 의미 있는 그림에는 `role="img"` + `aria-label`.
- 터치 대상 44×44px 이상, 대상 사이 간격 8px 이상.
- 폼: 모든 입력에 `<label>`, 오류는 `aria-describedby`로 연결하고 텍스트로 설명(색만으로 표시 금지). 입력 글자 16px 이상.
- 대화상자/시트: 포커스 트랩, Esc 닫기, 닫으면 포커스 복귀.
- 200% 확대에서 내용이 잘리지 않는다. 가로 스크롤 없음(390px, 320px에서도).
- 모션 대안: 4.3의 reduced-motion 규칙.

### 4.6 반응형 규칙 (adapt 스킬)

- 기준 화면: 390×844(필수 완벽), 768, 1024, 1440×900(필수 완벽). 320px에서도 깨지지 않게.
- 좌우 여백: 모바일 20px(최소 16px), 데스크톱 `clamp(24px, 4vw, 64px)`. 본문 열 최대 폭 65자 안팎.
- 글자: 본문 16px 이상(Gaegu, Gowun Dodum처럼 작아 보이는 폰트는 17~18px). 제목은 `clamp()`. 모바일에서 한국어 제목이 한 글자만 남아 줄바꿈되지 않게 `keep-all`과 `text-wrap: balance` 확인.
- 호버에 의존하는 정보는 터치에서 탭이나 항상 표시로 바꾼다.
- 고정 요소(내비, 하단 바, 컨셉 배지)끼리 겹치지 않게 한다. `env(safe-area-inset-*)` 반영.
- 데스크톱의 다단 레이아웃은 모바일에서 한 열로. 표는 가로 스크롤 대신 행 스택 또는 탭.

### 4.7 문구 규칙

- 생성하는 한국어 문구에 엠대시(—), 화살표(→, 버튼 끝), 느낌표 남발 금지. 가운뎃점으로 메타 정보를 줄줄이 잇지 않는다(브리프가 명시한 곳 제외).
- 제목 일부만 색이나 기울임으로 강조하지 않는다. 대문자 트래킹 라벨 금지(haeon-systems 히어로 키커 한 곳 제외).
- 제목은 효용으로 시작한다. 버튼은 동작을 말한다. 같은 동작은 페이지 끝까지 같은 이름.
- 스튜디오 홈페이지: 이 문서의 문구를 그대로. 지어낸 실적 금지.
- 목업: 가상의 가격과 후기는 허용. 실존 브랜드명, 실존 인물, 실제 상표 금지.

### 4.8 완료 기준 (페이지마다 전부 확인)

1. 로컬 서버에서 1440×900과 390×844로 열어 **스크린샷을 찍어 직접 본다**(첫 화면 + 아래 섹션들). 콘솔 오류 0.
2. 첫 화면: 로드 후 1.2초 안에 브랜드명, 헤드라인, CTA가 보인다. 2.5초 시점의 1440×900 화면이 썸네일로 쓸 만하다. `?shot=1`이 동작한다.
3. 390px에서 가로 스크롤 없음(`document.documentElement.scrollWidth === innerWidth`), 좌우 여백 16px 이상, 글자가 잘리거나 겹치지 않음.
4. JS를 끄고 열어도 모든 글과 주요 그림(또는 대체 화면)이 보인다.
5. `prefers-reduced-motion: reduce`를 에뮬레이션해도 내용이 모두 보이고 브리프의 정지 상태가 나온다.
6. Tab 키만으로 끝까지 이동 가능, 포커스가 항상 보인다, 커스텀 컨트롤이 키보드로 동작한다.
7. 브리프의 팔레트, 폰트(패밀리 2개 이하), 헤드라인, CTA가 그대로 쓰였다. 외부 이미지와 외부 스크립트 요청 0건(네트워크 탭에서 Google Fonts 외 외부 요청 없음).

9. 캔버스/WebGL은 화면 밖에서 멈추고, 실패 시 대체 화면이 나온다.
10. 목업: 컨셉 배지가 스펙대로 있고 `../../index.html#work`로 연결된다. 푸터 고지 문구가 있다. `noindex`가 있다.
11. design-review 스킬의 checklist.md 10개 항목(위계, 타이포, 간격, 색과 대비, 모션, 컴포넌트 상태, 접근성, 반응형, 문구, 일관성)으로 스스로 한 번 검토하고 막히는 문제를 고친다.
12. 0장의 안티 슬롭 목록을 다시 읽고, 브리프가 허용한 예외 외에는 해당 사항이 없는지 확인한다.
