# 검수: haeon-systems (해온 시스템즈, 대표작 M00)

## Verdict: **Fix** (Rework 아님, 아직 Ship 아님)

- 구성(왼쪽 텍스트 열 + 3/4 조감 야간 단지 + 시안 궤도)은 레퍼런스와 같은 문법이고, 2배율로 보면 크레인·터미널·관제탑의 만듦새가 좋다. 코드 품질(드로콜 30, 폴백, 정지 프레임, 접근성)은 포트폴리오 전체에서 최상급이다.
- 그러나 레퍼런스의 "느낌"에는 약 65~70%만 도달한다. 레퍼런스는 **빛이 물과 도로에 번지는 장면**(수면 반사, 발광하는 파란 도로, 환한 터미널, 수평선의 노을 띠)인데, 우리 장면은 평평한 남색 바다 위에 어두운 단지가 떠 있고, 궤도 위에 작은 점이 너무 많이 흩어져 "고요한 궤도"가 아니라 "반짝이 가루"로 읽힌다. 수평선은 헤더 뒤에 숨어 깊이가 사라졌다.
- 폰 첫 화면은 장면이 작고 어둡고 가파르게 내려다봐서 시그니처가 거의 전달되지 않는다. 히어로 아래 섹션은 깔끔하지만 히어로만큼의 야심은 없다(특히 솔루션 행). 아래 🔴 4건과 "레퍼런스에 더 가깝게" 1~3번을 처리하면 Ship.

스크린샷은 SwiftShader(소프트웨어 WebGL)로 본 것이므로 밝기 판단은 여러 해상도와 2배율 크롭을 교차 확인했다.

## Findings

### 🔴 반드시 고칠 것

**1. 바다가 죽어 있다: 반사와 수변 빛이 거의 안 보인다** (scene.js 1198~1300, 바다 셰이더 / 반사 쿼드 / light pool)
1440x900에서 단지 주변 수면이 균일한 `#0A1430`으로 보이고, 반사 줄무늬는 2번 부두 비컨 아래 한 줄만 간신히 보인다. 땅이 물 위에 "놓인 판"처럼 떠 보여 모형 느낌의 가장 큰 원인이다. 레퍼런스는 수면의 1/3이 건물 불빛으로 물든다.
- 반사 인스턴스 기본 알파 `rf[5] || 0.25` → `0.6`, 프래그먼트의 `pow(1.0 - vUv.y, 1.4)` → `pow(1.0 - vUv.y, 0.9)`(더 길게 늘어짐), 길이(aA의 높이 값) 1.6배.
- 터미널 수변 파사드(z=20 쪽, x 1.5~31.5)를 따라 3 단위 간격으로 따뜻한 반사 10개(색 `#FFC98A`, 폭 1.2, 길이 9, 알파 0.55), 타워 5동 방향으로 차가운 반사 6개(`#9FD4FF`, 폭 2, 길이 12, 알파 0.35) 추가.
- light pool `blob` 알파 전부 2배(0.16→0.32, 터미널 앞 `blob(16,34,26,…,0.2)` → 반지름 34, 0.4). 셰이더 `col += pool * (0.7 + …)` → `pool * (1.1 + …)`.
- 매립지 가장자리(안벽)에 따뜻한 발광 띠 1줄: 둘레 Shape를 따라 폭 0.12, 색 `#FFD9A8`, MeshBasic, 불투명도 0.8 + 물 쪽 폭 1.5 가산 헤일로 0.15. 레퍼런스에서 땅과 물의 경계를 읽게 해 주는 바로 그 선이다.
- 잔물결 하이라이트 `uCyan * 0.08 * streak` → `0.14`, `sFade`의 시작 `smoothstep(40.0, 85.0, dist)` → `(20.0, 60.0)`(단지 가까운 물에도 결이 보이게).

**2. 궤도 입자가 너무 많고 선이 너무 가늘다: "고요·프리미엄"이 아니라 산만** (scene.js 298 `perCurve`, 1089 `TAIL`, 궤도 셰이더 1055~1085)
한 프레임에 머리 점이 40개 이상 보이고(타원 6/8/10 + 호 4개분) 부두 가로등 점과 섞여 구분되지 않는다. 궤도선은 1px 미만으로 가늘어 타원 3개의 형태가 한눈에 안 읽힌다. 레퍼런스는 굵기 있는 타원 3~4개에 밝은 점 6~8개가 전부다.
- 입자 수: 타원 `[6, 8, 10]` → `[2, 3, 3]`, 호는 곡선당 1~2개(모바일 `[1, 2, 2]`). 총 12~14개.
- 머리 크기 0.5 → 0.8, 꼬리 4점 → 8점(간격 0.004 → 0.0035, 알파 1 → 0.06까지 지수 감쇠)로 "점"이 아니라 "짧은 혜성"이 되게.
- 궤도 코어 튜브 반지름 0.035 → 0.055, 헤일로 반지름 0.16 → 0.30 / 불투명도 0.10 → 0.20. 선 밝기 변조 하한 0.25 → 0.4(어둠으로 완전히 사라지는 구간이 지금은 "끊긴 선"처럼 보임).
- 속도는 유지(14~26초). 호 4개의 선 밝기는 타원의 70%로 낮춰 위계를 준다: 타원이 주인공, 호는 보조.

**3. 수평선·하늘·산이 헤더 뒤에 숨는다: 깊이감 상실** (scene.js 254 `CAMS.desk`, 1343~1365 하늘, 1405~1406 산)
1440x900에서 수평선이 y≈105px(11.6%), 능선이 y 40~105에 있어 내비 76px와 상단 스크림(`rgba(6,12,31,.4)` 120px)에 덮인다. 레퍼런스는 수평선 17%, 그 아래 섬과 노을 구름이 분명하다. 그리고 수평선(y 105)과 도시 윗단(y 180) 사이는 빈 물뿐이다.
- 카메라: `tgt [-3, 5, -16.6]` → `[-3, 9, -16.6]`, `pos [-59, 29, 65.5]` → `[-62, 31, 70]`. 수평선이 y≈150~160으로 내려오고 단지가 약간 작아져 오른쪽 잘림(8번)도 완화된다. 단지 아랫단이 서비스 줄(y 760)을 넘지 않는지 눈으로 맞출 것.
- 노을 띠: `uBand * 1.12` → `* 1.5`, 따뜻한 성분 `uWarm * 0.16` → `0.38`, 감쇠 `/ 0.7` → `/ 1.6`. 오른쪽 수평선에 분홍빛이 분명히 보여야 한다.
- 구름 띠 2~3줄: 하늘 셰이더에 `el` 2~7° 구간에 가로로 긴 저주파 노이즈(`sin` 3옥타브, x축 스케일 8배)로 어두운 구름 실루엣(`uZenith` 쪽으로 35% 섞기)을 추가. 레퍼런스의 깊이는 이 구름에서 나온다.
- 산: 앞 겹 `C(0x161b42)` 유지, 뒤 겹 꼭대기 `0x2a2a5e` → `0x3a3474`로 밝혀 두 겹이 분리되게. 원경 본토 해안에 불빛 점 띠(40~60개, 따뜻한 색, 크기 1.5px, 알파 0.5) 추가.
- CSS 상단 스크림 `rgba(6,12,31,.4) 0 → 0 120px` → `.28 0 → 0 84px`.

**4. 폰(390x844) 첫 화면에서 시그니처가 약하다** (CAMS.mob, style.css 325~339, 310 `.hero-stage`)
- 히어로 높이 1072px(뷰포트의 127%). 서비스 링크는 y 840~936, 트윈 스위치는 y 952~996이라 첫 화면에 없다. 첫 화면에 보이는 장면은 y 520~844(38%)뿐이고 그나마 스크림(34% 지점까지 0.82)과 하단 스크림에 눌려 어둡다. PLAN은 "장면이 히어로 아래쪽 55%".
- 카메라 `pos [-70, 90, 100]`는 고도 약 34°의 가파른 평면도 시점이라 타워가 납작하고 창불이 안 보인다. 320x640에서는 첫 화면에 궤도 윗부분만 걸린다.
- 수정: `CAMS.mob = { pos: [-52, 44, 82], tgt: [10, 6, -4], hfov: 30 }`(고도 약 20°, 타워 파사드가 보임). 폰 스크림 `0.94 0% / 0.82 34% / 0.15 54% / 0 62%` → `0.94 0% / 0.7 30% / 0 46%`. 본문을 폰에서 3줄로(`.hero-lead { font-size: .9375rem }` 또는 폰 전용 짧은 문장), 버튼 간격 12→8px, `.hero-stage` `clamp(240px, 38svh, 360px)` → `clamp(280px, 44svh, 420px)`, 서비스 2x2와 스위치는 장면 **위에 겹쳐** 히어로를 `100svh`에 맞춘다(스위치를 서비스 격자 오른쪽 위 줄로 올리면 1행 절약).
- 폰용 밝기: 모바일에서 `towerMat.emissiveIntensity` 1 → 1.5, 헤이즈 스프라이트 불투명도 1.5배. 작은 화면에서는 같은 밝기가 훨씬 어둡게 읽힌다.

### 🟠 고치면 확실히 좋아지는 것

**5. 도로가 빛나지 않는다** (scene.js 780~806 도로 텍스처, 1174 `TRAILS`)
레퍼런스의 두 번째 주인공은 전기 파랑으로 빛나는 도로망이다. 우리 도로는 `#111c3c` 아스팔트에 35% 회색 가장자리선이라 땅과 구분이 안 되고, 빛줄기는 화면에 3~4개만 보인다.
- 도로 가장자리선 `rgba(190,205,240,0.35)` → `rgba(95,212,255,0.85)`, 선 두께 2px → 3px. 도로 리본 위에 폭 2.8의 가산 헤일로 리본 1장(시안, 알파 0.10).
- `TRAILS` 30 → 56(모바일 28), 길이 `0.015` → `0.03`, 폭 `0.16` → `0.22`, 알파 `1.5` → `2.2`. 고가 곡선로는 난간 조명 점을 2배로 촘촘하게(다리 실루엣이 지금 거의 안 보인다).

**6. 왼쪽 스크림이 부두와 크레인을 먹는다** (style.css 222~228)
헤드라인이 "항만"인데 크레인 4기와 접안 선박(x 560~800)이 가장 어두운 영역이다. 스크림이 38% 지점에서 아직 0.55다. 텍스트는 굵은 흰색이라 그만큼 필요 없다.
- `linear-gradient(90deg, rgba(10,20,48,.9) 0%, rgba(10,20,48,.5) 26%, rgba(10,20,48,0) 46%)`.
- 야드 투광등: 크레인 붐 끝마다 따뜻한 스프라이트(크기 2.2, `#FFE2B8`, 알파 0.8) + 바닥 light pool(반지름 5, 알파 0.3). 현재 `flood` PointLight `[-15, 7, 5, 0xffd6a8, 60, 22]` 강도 60 → 110.
- 접안 선박: 선체가 남색이라 물과 구분이 안 된다. 선교를 `#DCE6FF` 계열로 밝히고 현창 불빛 한 줄 + 갑판 조명 3점, 흘수선 아래 반사 추가.

**7. 1024x768에서 본문과 버튼이 장면과 겹친다** (V-1024x768)
본문 첫 줄 끝 "현장의 신호를"과 보조 버튼 오른쪽 끝 위로 궤도선·입자·부두가 지나간다. 1280x720에서도 h1 마지막 글자 "다"가 관제탑 상부와 14px 간격.
- `aspect < 1.6` 분기에서 가로 화각만 유지하지 말고 대상도 오른쪽으로 민다: 900~1180px 구간은 `tgt.x`를 -3 → -10(장면이 화면 오른쪽으로 약 70px 이동). 또는 그 구간에서 `.hero-lead { max-width: 22em }`.
- 서비스 링크 호버 시 카메라 접근(15%)으로 관제탑이 h1 끝 "다"에 닿는다(hover "디지털 트윈"에서 확인). `pos.lerp(focusNode, 0.1)` → `0.07`, 관제탑 노드만 `tgt.lerp` 0.2 → 0.12.

**8. 1440x900 구도: 터미널이 오른쪽 가장자리에서 잘린다**
가장 따뜻하고 밝은 덩어리(터미널)가 x 1100~1440에서 잘려 나가고 에너지 노드 비컨이 x≈1340, 가장자리 100px 안쪽에 있다. 썸네일(스튜디오 첫 카드)에서 오른쪽이 무겁고 잘린 인상이다. 3번의 카메라 후퇴로 6~8% 작아지면 대부분 해결된다. 그래도 잘리면 `tgt.x` -3 → +1. 터미널 지붕 끝이 화면 안 40px 이상 들어오게.

**9. 나무가 검은 공이다** (scene.js 871~900)
2배율 크롭에서 가장 "장난감"으로 읽히는 요소. 거의 검은 20면체가 땅 위에 굴러다니는 공처럼 보인다.
- 색을 `#0d2a2a`~`#143a30` 사이로 올리고, 세로 스케일 1.3~1.8 무작위(타원체), 인스턴스 색 밝기 ±25%. 가로등 근처 나무는 윗면에 따뜻한 정점색.
- 공원 바닥을 `#0f2430` 톤의 별도 색 면으로 깔아 나무가 "잔디 위"에 있게.

**10. 정체 모를 흰 점들** (halos/lights, 부두와 갑판 위)
부두 상판, 선박 갑판, 수면 위에 기둥 없는 흰 점이 30개 이상 떠 있어(Z-crop-c) 먼지처럼 보이고 2번의 입자와 섞인다. 가로등 기둥이 있는 것만 남기거나, 부두 가장자리를 따라 **일정 간격**으로 정렬(간격 3 단위, 따뜻한 색 `#FFD9A8`, 크기 통일). 무작위 배치는 금물이다. 레퍼런스의 점 조명은 전부 줄을 맞춰 서 있다.

**11. JS 꺼짐 + 폰: 내비가 키커와 겹친다** (style.css 186~191)
390px, JS 없음에서 `솔루션 / 구축 사례 / 기술` 줄(y≈70)이 히어로 키커 `Sense · Predict · Operate`(y≈86)를 덮는다. 헤더가 2줄(약 108px)이 되는데 히어로 상단 패딩은 64px 기준이다.
- `html:not(.js) .hero-inner { padding-top: calc(108px + 28px); }`(<768px 한정).

**12. 건물 창불의 재질감** (windowTexture, towerMat)
모든 동이 같은 격자 크기에 평면 발광이라 가까운 타워가 "픽셀 스티커"처럼 보인다. 유리 느낌이 없다.
- 타워 2~3동은 층 띠(가로로 이어진 커튼월) 텍스처로 바꾸고, 켜진 칸의 밝기를 0.5~1.0으로 흩뜨릴 것(지금은 on/off 2단계).
- 파사드에 수직 그라디언트: 정점색으로 아래 0.75 → 위 1.15(하늘 반사 흉내), `metalness 0.3 → 0.6`, `roughness 0.55 → 0.35`로 달빛 하이라이트가 면에 걸리게.
- 옥상 왕관 조명(현재 2번 타워 시안 띠만 뚜렷)을 5동 모두에. 꼭대기에 빨간 항공등 대신 작은 흰 점 1개씩.

**13. 솔루션 섹션이 히어로에 비해 평범하다** (#solutions)
행마다 240px짜리 선화가 오른쪽 끝에 작게 붙고, 불릿과 도해 사이 300px가 비어 있다. 제목 블록과 첫 행 사이도 100px 넘게 빈다. 대표작의 두 번째 화면인데 "표"처럼 읽힌다.
- 도해를 320~360px로 키우고 각 행에 수치 한 줄(Sora, 예: `갱신 주기 1초`, `모델 정밀도 5cm`)을 추가해 3열을 채운다.
- 호버/포커스 시 도해의 시안 경로에 점이 한 번 흐르게(MotionPath 1.2초). 지금 호버 반응은 배경 2% 변화뿐이다.
- 가능하면 각 행에서 히어로의 해당 노드 색/아이콘(`svc-ring`)을 반복해 히어로 하단 링크와 시각적으로 이어 준다.

**14. 폰 대시보드의 전력 곡선 라벨이 읽히지 않는다** (.panel-energy SVG)
348px 폭에서 축 숫자와 `예측 피크 4.1` / `조정 후 3.4` 범례가 약 5~6px로 축소된다. 범례를 SVG 밖 HTML로 빼고(13px), 축 라벨은 <640px에서 `font-size`를 뷰박스 기준 2배로 하거나 폰 전용 뷰박스(가로 360)를 쓴다.

### 🟡 다듬기

**15. 트윈 모드가 실사 모드보다 예쁘다.** 좋은 신호이자 경고다. 트윈의 엣지 선과 격자가 주는 선명함을 실사 모드에 조금 빌려 올 것: 건물 윗단 테두리에 가는 림 라이트(엣지 LineSegments를 실사 모드에서도 알파 0.12로 유지).

**16. WebGL 불가 시 트윈 스위치.** 폴백 SVG에서 스위치가 보이고 CSS로 일부 도형만 선으로 바뀐다. 동작은 하지만 창문 `rect`가 전부 투명해져 장면이 비어 보인다. 폴백에서는 스위치를 숨기거나(`html:not(.has-webgl):not(.webgl-pending) .twin-toggle { display:none }`) 창문은 유지.

**17. 폴백 SVG의 타워 창문**이 기울어진 색종이처럼 보이고(S-nogl) 폰에서는 보조 버튼 뒤에 타워 창이 깔린다. 폰 폴백은 `preserveAspectRatio`를 `xMidYMax slice`로 해서 건물을 버튼 아래로 내릴 것.

**18. 모바일 메뉴 패널 아래 배경 처리.** 메뉴가 y≈280에서 끝나고 바로 아래 히어로 본문이 잘린 채 보인다. 패널 아래에 `rgba(6,12,31,.6)` 배경막을 깔거나 패널 하단에 24px 페이드.

**19. 폼 완료 상태.** 제출 후 폼 카드가 작은 확인 카드로 줄면서 오른쪽 열이 비고, `done.focus()`만 하므로 제목이 고정 헤더에 가려질 수 있다. `.form-done { scroll-margin-top: 96px; min-height: 320px }` + `done.scrollIntoView({ block: 'nearest' })`.

**20. `mobile` 플래그가 생성 시 1회 고정** (main.js `mobile: window.innerWidth < 768`). 회전하거나 창을 줄여도 DPR 상한·개수가 안 바뀐다. 카메라는 `isMobileView()`로 다시 잡으니 실해는 작다. 최소한 `maxDpr`만 `resize()`에서 다시 계산.

**21. 이동 선박(페리)이 눈에 띄지 않는다.** 8초 관찰 동안 화면에서 움직이는 배를 찾지 못했다. 경로를 화면 왼쪽 아래 빈 바다(텍스트 열 아래, x 250~550 / y 640~720)로 지나가게 하고 항적(wake) 알파 0.35 → 0.6, 선실 불빛을 밝게. 왼쪽 1/3의 빈 바다에 생기를 준다.

**22. 인트로.** 0.5초 시점에 이미 궤도가 대부분 그려져 있다(소프트웨어 렌더 지연 영향일 수 있음). 실기기에서 `INTRO_DRAW 1.2s`가 체감되는지 확인하고, 타원 3개를 0.15초씩 시차를 두고 그리면 "그려지는" 순간이 더 읽힌다(현재 시차 `p.k * 0.025`는 너무 작다 → 0.12).

**23. 체크박스 24x24.** 라벨 전체가 눌리므로 실사용은 문제없지만 박스 자체를 28px로, 라벨 `min-height: 44px` 확인.

## 레퍼런스에 더 가깝게 (시각 효과 큰 순, Three.js 코어로 몇 시간 내)

1. **빛나는 물** (1번). 반사 줄무늬 강화 + 안벽 발광 띠 + light pool 2배. 가장 싸고 가장 큰 변화다. 땅이 물에 "닿는다".
2. **수평선을 내리고 노을·구름·먼 해안 불빛을 넣는다** (3번). 카메라 tgt.y +4, 하늘 셰이더에 구름 띠, 따뜻한 성분 2.4배. 화면 상단 20%가 "배경색"에서 "풍경"이 된다.
3. **궤도를 굵고 적게** (2번). 입자 40+ → 12~14, 코어 1.6배, 헤일로 2배, 혜성 꼬리. 레퍼런스의 차분함은 "적고 또렷함"에서 온다.
4. **발광 도로망 + 빛줄기 2배** (5번). 시안 가장자리선 + 가산 헤일로 리본. 단지에 "혈관"이 생긴다.
5. **가짜 블룸 한 겹**: 밝은 요소(터미널 띠 조명, 관제실, 왕관 조명, 투광등)마다 가산 스프라이트를 지금의 2배 크기·절반 알파로 하나씩 더 겹치고, 단지 전체 헤이즈 `[20,7,-10,110,36,0x4a5cb0,0.2]`를 0.3으로. 후처리 없이 "빛이 공기에 번지는" 느낌. 드로콜 증가 없음(기존 Points/스프라이트 버퍼에 추가).
