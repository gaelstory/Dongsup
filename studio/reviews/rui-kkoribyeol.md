# Refactoring UI 검토: kkoribyeol (꼬리별 강아지 유치원)

**Step 0:** 정적 HTML + 순수 CSS(`style.css` 440줄) + inline SVG + GSAP, Tailwind 없음, 컴포넌트 라이브러리 없음. `:root`에 색 토큰 10개(`--grass --ball --cream --nose --tongue --sky` + 파생 `--grass-back --grass-tuft --nose-soft --line`), 배치 토큰(`--gutter --header-h --dog-h --ground --grass-h`). 글자 크기, 간격, 반경, 그림자 토큰은 없음. 다크 모드 없음. 기준은 이 페이지의 "두꺼운 테두리 + 단색 오프셋 그림자 스티커" 시스템이다.

**검증:** 렌더 확인. `shoot.mjs` 1440/390 전 장면(`studio/.shots/rui-kkoribyeol/kkoribyeol/`) + 자체 캡처 1280/375 전 장면(`studio/.shots/rui-kkoribyeol/own/`의 `d1280-NN`, `m375-NN`). 대비는 `check_contrast.py`로 계산.

**전체 인상**
- 싸 보이게 만드는 것: 눈에 띄는 결함은 거의 없다. 다만 값이 흩어져 있다. 글자 크기가 고정 16종(Jua만 15~28px 사이 11단), 반경이 19종, 간격이 37종이다. 스티커 한 장 한 장은 귀여운데 카드마다 모서리 둥글기와 본문 크기(16/17/18px)가 조금씩 달라 "손으로 맞춘" 티가 난다.
- 노란 채움 버튼 `등원 상담 신청`이 첫 화면에 2개이고, 입력칸 placeholder가 4.18:1로 기준에 살짝 못 미친다.
- 이미 잘 된 점: 색 면 위 글자가 전부 코 색 계열이라 대비가 6.4~12:1(잔디 위 흰 글자 없음), 굵기는 두 글꼴 400 한 단뿐이라 위계를 글꼴(Jua/Gowun Dodum)과 크기로만 낸다. 요금 숫자가 화면에서 제일 크고 단위는 작다. 구역마다 배경색과 물결 구분선이 바뀌고, 약속 카드 3장이 모양과 높이가 달라 카드 격자 느낌이 없다. 스티커 그림자의 방향이 전부 오른쪽 아래로 일관된다.

## 토큰 정리

**글자 크기** (고정 16종 → 7종, clamp 6종 → 5종)

| 토큰 | 값 | 흡수하는 현재 값 |
|---|---|---|
| `--fs-xs` | 14px | 14(눈금, 통계 라벨), 15(날짜, `선택`, 오류, 푸터 고지, 로고 보조) |
| `--fs-sm` | 16px | 16(알림장 칩, 캡션, 작은 말풍선), 17(일과 카드 본문, 입력칸, 작은 버튼, 통계 값) |

| `--fs-lg` | 21px | 20(말풍선, 페이지 번호, 몸무게 라벨), 21(히어로 보조, 세그먼트, 칩 제목), 22(모바일 메뉴, 큰 버튼, 약도), 23(알림장 문장) |

| `--fs-3xl` | 38px | 38(단계 번호), 46(900px 이상 단계 번호는 원 크기에 맞춰 예외 유지 가능) |
| 제목 | clamp 5종 | 히어로, h2, 신청서 제목, 금액, 푸터 로고 |

`.section-lead`(19)와 body(18)는 1px 차이라 구분이 안 된다. 리드로 세우려면 `--fs-lg`(21, 히어로 보조와 같은 단)로, 아니면 18로 합친다.

**간격** (37종 → 9단): `--s-1: 4px` … `--s-9: 96px`(4/8/12/16/24/32/48/64/96). 간격 토큰이 없어서 책의 기본 스케일로 대체했다. 매핑: 2/3/5/6→4 또는 8, 10/11→8 또는 12, 14→12 또는 16, 18/20/22→16 또는 24, 26/28/30→24 또는 32, 34/36/40/44→32 또는 48, 52/56→48, 70/72→64. 스티커 위치값(`top: -48px`, 덩어리 `padding-top: 112px`, 엇갈림 `110px`)은 그림 배치라 예외.

**반경** 19종 → `--r-sm: 14px` / `--r-md: 20px` / `--r-lg: 36px` / 999px·50%. **그림자** 6값 → `--pop-1`~`--pop-5`. **테두리** → `--bd: 2px` / `--bd-lg: 3px`. **색** → 신규 토큰 6개(`--white`, `--pink`, `--mint`, `--grass-ink`, `--danger`, `--placeholder`).

## 확인한 것과 확인하지 못한 것

- 확인: 1440/1280/390/375 전 스크롤 장면, reduced-motion 1장. 본문 폭과 줄 수(계산된 스타일로 측정: 데스크톱 16~35em, 폰 일과 카드 11.2~12.8em), 대비 14쌍(코 색: 잔디 위 6.45:1, 노랑 위 12.14:1. 시간 초록 6.03:1, 공 개수 5.39:1, 오류 6.39:1 통과. 미달은 placeholder 4.18:1 하나).
- 확인 못 함: 폼 오류 상태(8번은 코드로만 봄)와 완료 화면, 열린 모바일 메뉴, 호텔 요금 토글, 알림장 2~3쪽, 공을 던진 뒤의 장면, 호버와 포커스 모습. 6번 수정 뒤 발자국 경로의 위치, 4번과 7번 토큰 적용 뒤의 모습은 렌더로 비교하지 않았다. 캡처는 DPR 1, 소프트웨어 렌더.
