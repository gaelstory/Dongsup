# Refactoring UI 진단: 서른여섯 사진관 (`work/film36/`)

**Step 0:** 순수 HTML + CSS + JS(GSAP ScrollTrigger, Flip), Tailwind 없음, 컴포넌트 라이브러리 없음. `:root` 토큰은 색 6개(`--dark --chem --safe --paper --silver --base`)와 `--line`, 폰트 2개, `--g`, 이징 2개. 글자 크기, 간격, 그림자 토큰은 없음. 다크 전용(`color-scheme: dark`).
**검증:** 1440×900, 390×844(`shoot.mjs`)과 1280×800, 375×812(직접 촬영) 화면을 전부 보고 판단. 상품 행 호버 상태는 따로 촬영. 표의 "코드"는 화면으로 확인하지 못한 항목.

**전체 인상**
- 싸 보이게 만드는 것: 어두운 면 위의 글자 단계가 토큰이 아니라 투명도로 그때그때 만들어졌다(인화지색 .82 / .86 / .88, 은염 .8). 크기도 14~20px 사이가 1px 간격으로 다 쓰이고, h2가 64px과 60px 두 가지다. 한 장면씩 보면 멋있지만 "한 벌"이라는 느낌이 약해진다.
- 폰에서 위계가 눌린다: h1(36px)과 h2(34px)가 거의 같은 크기이고, 현상 트레이의 큰 그림자가 헤드라인 첫 줄 위에 떨어져 첫 줄만 회색으로 보인다.
- 이미 잘 된 점: 세이프라이트 빨강을 큰 숫자와 면에만 쓰는 브리프가 지켜진다(단계 번호 76px 3.52:1은 큰 글자 기준 통과). 본문 대비는 전부 6:1 이상. 굵기는 400/700 + Bodoni 500으로 정리돼 있다. 폼은 라벨과 입력 사이(12px)가 필드 사이(37px)보다 좁아 그룹이 분명하다. 셀렉 0개 상태 문구도 있다.

## 토큰 정리

| 종류 | 현재 | 제안 스케일 |
|---|---|---|
| 글자 크기 | 고정 17종 + clamp 8종(h2만 2종) | `12 / 15 / 17 / 22 / 28 / 44 / 64 / 88`, h2 clamp 1종 |
| 줄 간격 | 9종, 1.85가 77곳 | `1 / 1.22 / 1.65 / 1.85` (.9, 1.14, 1.2→1 또는 1.22, 1.6·1.7·1.75→1.65) |
| 간격 | 42종 | `4 8 12 16 24 32 40 48 72 96 120 152` |
| 어두운 면 글자 색 | 6단계(투명도 4종 포함) | `--paper` / `--paper-2 #D2CEC7` / `--silver` |
| UI 색 | hex 29개, rgba 45개 | 팔레트 6색 + `--paper-2 --safe-deep --err --ink --ink-2`. 선은 `--line` 하나(현재 .32, .4, .45, .5 테두리도 `rgba(241,238,230,.4)` 한 값 `--line-strong`으로) |
| 그림자 | 6종 직접 표기 | `--shadow-print`, `--shadow-sheet` + 트레이 전용 1종 |

팔레트 6색, 서체 2종, 2px 반경, 1px 선은 브리프대로 유지.

## 확인한 것과 확인하지 못한 것

확인한 것
- 열두 법칙: 섹션당 주 행동 1개(통과, 다만 모양이 두 가지 → 6번), 글자 색 3개 이하(위반 → 5번), 굵기 400/700 + Bodoni 500(통과), 문단 폭(통과, 최대 34em), 그룹 간격 > 내부 간격(통과), 시스템 값(4·9·10·11번), 색 배경 위 회색 글자(투명도 처리 → 5번), 빛은 위에서(통과, 그림자 x=0), 색만으로 전달(통과: 셀렉은 동그라미 + 개수 문구, 릴 진행은 숫자).
- 대비(`check_contrast.py`): 인화지/세이프 4.93, 암실/인화지 17.37, 세이프/암실 3.52(큰 글자만 허용), 세이프/약품 3.33(큰 글자만), 은염/암실 7.13, 은염/약품 6.75, placeholder(은염 .8 → `#807E7B`)/약품 4.71, 필름베이스/암실 7.31, 필름베이스/필름 6.20, `#5E5A54`/인화지 5.60, `#FF8F94`/암실 9.22.
- 상품 행 호버 화면을 촬영해 1번을 확인. 폰 헤드라인 첫 줄이 어두운 원인을 요소 겹침 순서로 확인(2번).
- 가로 넘침 없음(1440, 1280, 390, 375), 콘솔 오류 0.

확인하지 못한 것
- 폼 오류 상태(`aria-invalid`, `.field__err`), 제출 완료 화면, 컷 뷰어 모달, 루페, 모바일 메뉴 펼침은 촬영하지 않았다(11번의 오류색은 코드 기준).
- 7번은 1280×800에서만 재현. 1366×768 같은 더 낮은 화면은 계산상 같은 문제가 예상되지만 촬영하지 않았다.
- 15번 달력 아이콘은 헤드리스 Chromium 렌더 기준. Safari, Firefox는 확인하지 않았다.
- 릴 캡션 옆 고정 "컨셉 시안" 배지가 캡션을 가리는 것은 스튜디오 공통 배지라 이 페이지 결함으로 올리지 않았다.
