# Refactoring UI 검토: ieum-architects (이음 건축사사무소)

**Step 0:** 정적 HTML + 순수 CSS(`style.css` 688줄) + GSAP/Three.js, Tailwind 없음, 컴포넌트 라이브러리 없음. `:root`에 색 토큰 10개(`--blue --deep --chalk --trace --marker --marker-hi --err --line --line-soft --focus`)와 글꼴 2종은 있으나 **글자 크기, 간격, 그림자 토큰은 없음**. 다크 모드 없음(청사진 단일 테마, `color-scheme: dark` 고정). 페이지 자체 시스템이 우선이므로 아래 제안은 모두 이 토큰 이름으로 적었다.

**검증:** 렌더 확인. `shoot.mjs` 1440/390 전 장면 + 자체 캡처 1280/375 전 장면.

**전체 인상**
- 싸 보이게 만드는 것: 12~19px 사이에 글자 크기가 1px 간격으로 8단계 있고, 간격 값도 10/12/14/16/18/20/22/24처럼 2px씩 다르다. 한 화면에서는 티가 안 나지만 섹션을 넘길 때 "미세하게 안 맞는" 느낌의 원인이다.
- 본문 대부분(보이는 글자의 62%)이 굵기 300인데, 그중 보조색(`--trace`)이나 14px와 겹치는 곳은 선이 가늘어 청사진 위에서 힘이 빠진다.
- 이미 잘 된 점: 주황(`--marker`) 하나만 강조색으로 쓰는 절제, 반경 2px 통일, 그림자 사실상 0개(색 대비로 깊이 표현), 표의 면적 열 오른쪽 정렬, 라벨과 값의 위계(`설계비 예시` 작게, 금액 크게), 모든 문단이 20~36em 안에 들어온다.

## 토큰 정리

**글자 크기** (고정 11종 + 유동 6종 → 고정 6종 + 유동 3종)

| 새 토큰 | 값 | 흡수하는 현재 값 |
|---|---|---|
| `--fs-xs` | 12px | 12 (구역 번호, 축척, 산출물 꼬리표, 모바일 표제란). `:441`의 9px 평면 글자는 SVG 단위라 제외 |
| `--fs-sm` | 14px | 13, 14 (로고 부제, 표 머리, 표제란, 주석, 푸터) |
| `--fs-md` | 16px | 15, 16 (내비, 폼 라벨, 선택지, 단계 번호, 모바일 본문) |
| `--fs-lg` | 18px | 17, 18, 19 (데스크톱 본문, 리드, 히어로 리드, 인용) |
| `--fs-xl` | 22px | 22, `clamp(18px,1.7vw,22px)` (표 프로젝트 이름, 결과값) |
| `--fs-2xl` | 28px | 26, `clamp(22px,1.9vw,28px)`, `clamp(26px,2.6vw,34px)` |
| 유지 | clamp 3종 | 히어로 36~72, 섹션 30~52, 장 제목 28~40. `44px` 평수 숫자는 장 제목 clamp로 |

**간격**: 위 5번의 9단계. 가장 많이 쓰는 12(23회), 8(15회), 16, 24는 그대로이고 10/14/18/22만 옮기면 된다.

**색**: 투명도 변형이 37종(`rgba(242,245,252,…)` 14종, `rgba(169,190,240,…)` 10종 등). 선은 `--line`(0.24), `--line-soft`(0.12) 두 토큰이 이미 있으니 `rgba(169,190,240,0.16~0.6)` 8종을 `--line-trace: rgba(169,190,240,0.5)`와 `--line-soft` 둘로 묶는다. 헤더 배경 `rgba(23,64,176,0.84)`, 패널 `rgba(10,28,85,0.6/0.78)`은 `--surface-header`, `--surface-inset` 토큰으로.

**굵기**: 300/400/600 3종 → 400/600 2종(2번 채택 시).

**그림자/반경**: 그림자 1종(`plan-float`, 세로만, 2단)과 반경 2px 통일. 손댈 것 없음.

## 확인한 것

- `shoot.mjs` 결과(`studio/.shots/rui-ieum-architects/ieum-architects/`): 로드, 데스크톱 12장, 폰 12장, reduced-motion 1장 전부 열람.
- 자체 캡처 1280×800 12장, 375×812 12장(`studio/.shots/rui-ieum-architects/w1280-375/`).
- CSS에서 글자 크기, 굵기, 줄높이, 간격, 색, 반경, 그림자 값을 세고, 렌더된 페이지에서 계산 스타일로 글자 크기/굵기/색별 글자 수와 문단별 폭(em)을 측정.
- 대비: `check_contrast.py`로 16쌍 계산. `--trace` on `--blue` 4.72, on `--deep` 8.63, `--chalk` on `--blue` 8.03, 버튼 6.15, 플레이스홀더 5.14, 오류색 7.51, 밝은 섹션 3색 8.03~10.53 모두 통과. 실패는 1번뿐.
- 열두 법칙: 1차 행동(7번), 글자색(3번), 굵기(2번), 행 길이(8번 외 통과), 그룹 간격(6번), 시스템 값(4, 5번), 색 배경 위 회색 글자(없음: `--trace`는 배경과 같은 파랑 계열), 빛 방향(그림자 1개, 세로), 색만으로 전달(없음: 선택지는 테두리+점, 진행 눈금은 장 번호와 병기).

## 확인하지 못한 것

- 표 행 호버의 떠 있는 평면 틀, 행 펼침, 폼 오류/성공 상태, 모바일 메뉴 패널은 이번에 다시 띄워 보지 않았다(코드로만 확인, 지난 QA에서 동작은 검증됨).
- 굵기 300의 실제 기기 렌더(윈도우 ClearType, 저해상도 화면)는 헤드리스 캡처로만 판단했다.
- 5번 간격 매핑을 적용했을 때 도면 표제란처럼 px 단위로 맞춘 부분이 어긋나는지는 적용 후 재확인 필요.
