# Refactoring UI 감사: 딱정산 (`work/ddak-saas/`)

**Step 0:** 순수 HTML + CSS(`style.css`) + GSAP, Tailwind 없음, 컴포넌트 라이브러리 없음, `:root`에 자체 토큰 있음(색 9개, 채널색 4개, 그림자 3단 `--sh-sm/md/lg`, `--gutter`), 다크 모드 없음(`color-scheme: light`). 글자 크기·간격·반경은 토큰이 없음.
**검증:** 1440×900, 390×844(`shoot.mjs`), 1280×800, 375×812(직접 촬영)에서 렌더 확인. 표의 위치는 모두 `work/ddak-saas/style.css` 기준 줄 번호.

**전체 인상**
- 이미 잘 된 점: 화면마다 주인공이 분명하다(히어로 제목 → 앱 창 → 단계 → 요금). 본문 폭이 26~34em으로 잡혀 있고, 숫자는 Space Grotesk 표 숫자로 오른쪽 정렬, 색 배경 위 글자는 회색이 아니라 흰색/라벤더 톤이다. 그림자도 3단 토큰으로 묶여 있다.
- 싸 보이게 만드는 것: 값이 "눈대중으로 0.5px씩" 흩어져 있다. 글자 크기가 11.5부터 17px까지 0.5px 간격으로 12단계, 반경이 15종, 간격이 41종이라 앱 창 안쪽이 미세하게 안 맞는 느낌을 준다.
- 실제 사용에 걸리는 것은 두 군데뿐이다. 휴대폰 폭의 `맞추기` 표가 채널을 색 점만으로 구분하고, 파일 배지(XLS/PDF)의 흰 글자가 대비 기준에 못 미친다.

## 확인한 것

- 열두 법칙 점검: 주 액션(히어로만 위반, #3), 글자색(#4), 굵기 400 미만 없음, 본문 폭 26~34em 통과(FAQ만 #10), 그룹 간격은 바깥 > 안쪽 통과(패널 머리 12px < 패널 사이 16px 이상, 섹션 머리 36~56px < 섹션 80~128px), 색 배경 위 회색 글자 없음(바이올렛 띠는 흰색, 푸터는 `#D8D5E5` 12.7:1), 빛 방향 위에서 아래 통과(모든 그림자 Y 양수), 색만으로 전달(#1).
- 대비 계산(`check_contrast.py`): `--fog` on 흰색 5.36, on `--lav` 4.60, on `--tray` 5.12, on `#F2F0F7` 4.74 / `--violet-text` on `--lav` 5.97 / 흰색 on `--violet` 5.70 / placeholder `#737086` 4.78. 모두 통과.
- 큰 요소가 작은 요소보다 빨리 줄어드는지: 히어로 제목 66 → 38px, 본문 16.5px 고정. 통과.

## 확인하지 못한 것

- FAQ 답변 폭(#10)과 팝오버, 가입 폼 오류 상태는 닫힌 상태로만 촬영해 코드로만 판단.
- 호버, 포커스, `직접 해보기` 수동 모드는 렌더로 보지 않음.
- 1024~1199px 구간과 높이 760px 이하 분기(`:624-648`)는 촬영하지 않음.
