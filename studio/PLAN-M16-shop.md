### M16. `seorijae` 서리재 SEORIJAE · 한줌 라이트 다운 26 겨울 기획전

- **브랜드:** 서리재 / SEORIJAE (가상의 아웃도어·테크 어패럴 브랜드). "재"는 산을 넘는 고갯길. 서리가 내린 고개를 넘는 사람을 위한 가벼운 옷을 만든다는 설정.

- **업종/카테고리:** 아웃도어 의류 자사몰 기획전 / **쇼핑몰**(홈페이지 포트폴리오의 새 카테고리. 등록 정보는 문서 끝 참조). **대상:** 가벼운 겨울 산행과 출퇴근을 한 벌로 해결하려는 20~40대. **패키지:** 맞춤 화면(쇼핑 기능 가정).

  - 라인 로고타입(히어로, 전면 컷에서 반복): 두 줄. 1행 `HANJUM` Archivo 800 wdth 125, 자간 -0.01em, **글자 채움에 가로 그라디언트**(서리 백 0~55% → 잔불 100%. `background-clip: text`, 미지원 시 서리 백 단색). 2행 `LIGHT DOWN 26W` Archivo 500 **wdth 62**, 자간 0.34em, 서리 백. 1행 너비에 2행의 양끝이 맞게 자간으로 조정한다. 넓은 글자와 좁은 글자의 대비가 우리 워드마크다.

- **규칙 예외(이것 외에는 없다):**
  1. **대문자 자간 라틴 라벨 허용.** 주인이 원한 레퍼런스의 기술적 분위기에 필수다. 쓰는 곳은 서브 탭, 기능 도해의 명칭, 스펙 칩, 아이콘 행, 룩북 측면 라벨, 상품 카드의 색 이름, 태그라인에 한정한다. **섹션 제목 위에 아이브로처럼 얹지 않는다.** 한글 h2 위에는 라벨이 없다.
  2. **"큰 연출 하나" 규칙의 확장.** 기획전 페이지라 주인이 요청한 연출이 넷이다(모델 띠, 도해, 큰 글자, 원통). 넷 모두 **같은 한 가지 아이디어(접힘 → 부풂)** 의 변주로 묶고, 각자 자기 섹션 안에서만, 한 번에 하나씩만 움직인다. 첫 화면의 시그니처는 모델 띠다. 그 밖의 섹션 입장 애니메이션은 넣지 않는다.
  3. **같은 모양의 상품 카드 5장 한 줄 허용.** 쇼핑몰의 상품 목록은 비교가 목적이라 균일해야 한다. 대신 카드에 배경, 테두리, 그림자를 주지 않는다(이미지 면 + 글자).
  4. **퀵뷰 시트의 버튼 2개(`장바구니 담기`, `바로 구매`) 허용.** 실제로 다른 동작이다.
  5. **`font-variation-settings` 스크롤 스크럽 허용**(큰 글자 섹션 한 곳). transform이 아니지만 높이를 고정해 레이아웃 이동이 없고 대상이 글자 세 덩어리뿐이다.
  6. 로고타입 1행의 그라디언트는 로고의 일부이므로 "제목 일부만 색으로 강조 금지"에 해당하지 않는다. h1, h2에는 그라디언트를 쓰지 않는다.
  7. 가격, 리뷰 수, 재고는 가상의 값이다(목업 허용). 푸터 고지로 충분하다.

#### 1. 파일 구성

```
studio/work/seorijae/
  index.html
  style.css
  jacket.js     재킷 렌더러 (window.SRJ.jacket)
  scenes.js     풍경·모델 장면 렌더러 (window.SRJ.scenes)
  main.js       맨 위에 PHOTOS 설정, 상품 데이터, 상태, UI, 모션
  photos/README.txt   사진 교체 방법 6~10줄(파일 이름 규칙, 권장 크기). 이 폴더에 이미지는 넣지 않는다.
```

- 스크립트는 전부 **일반 `defer` 스크립트**(모듈 아님)로 `gsap.min.js` → `ScrollTrigger` → `Draggable` → `InertiaPlugin` → `DrawSVGPlugin` → `Flip` → `jacket.js` → `scenes.js` → `main.js` → `../../assets/shared/concept-badge.js` 순서. 다른 플러그인, Three.js, Lenis는 로드하지 않는다(WebGL을 쓰지 않는 목업이다. 전부 Canvas 2D + SVG + CSS 3D).
- `<title>서리재 SEORIJAE | 컨셉 시안 · 첫화면 스튜디오</title>`, `<meta name="robots" content="noindex">`, description: `한 줌으로 접히는 248g 구스 다운, 서리재 한줌 26 겨울 기획전. 첫화면 스튜디오의 쇼핑몰 컨셉 시안입니다.` 파비콘: 현무 배경에 잔불 점이 든 V선 SVG data URI.
- 직접 쓴 JS 합계 110KB 이하(main 55, jacket 30, scenes 25 안팎), 페이지 전체 250KB 이하.

#### 2. 사진 교체 설정 (`main.js` 맨 위, 그대로 둔다)

```js
// 실제 촬영 사진이 생기면 ./photos/ 폴더에 넣고 경로만 채우면 된다. 비워 두면 코드로 그린 그림이 나온다.
const PHOTOS = {
  heroModels: [],   // 최대 5장. './photos/hero-1.jpg' 또는 { src, alt, color: 'ember', focal: '50% 30%' }
  lookbook:   [],   // 최대 10장. 앞 5장 공용 핏, 뒤 5장 여성 핏. 세로 3:4.4
  fullBleed:  '',   // 전면 컷 1장. 가로 16:9 이상
  products:   {}    // { 'hanjum-hoody': { ember: ['./photos/hoody-ember-front.jpg', './photos/hoody-ember-back.jpg'] } }
};
```

- **기본값은 전부 빈 값이고, 그 상태가 이 목업의 완성본이다.** 빈 값일 때는 `./photos/`에 대한 요청을 **한 건도 보내지 않는다**(존재 확인용 요청 금지. report.json의 실패 요청 0건 유지).
- 허용 경로는 `./photos/`로 시작하고 `.jpg|.jpeg|.png|.webp|.avif`로 끝나는 상대 경로뿐이다. 정규식으로 검사해 그 외(`http`, `//`, `data:`, `..` 포함)는 무시하고 코드 그림을 쓴다. 외부 사진은 어떤 경우에도 참조하지 않는다.
- 슬롯 단위로 동작한다. `heroModels[2]`만 있으면 3번 패널만 사진, 나머지는 코드 그림. 사진은 `<img loading="lazy" decoding="async" alt>`에 `object-fit: cover`, `object-position: focal`. `error` 이벤트가 나면 그 `<img>`를 떼고 같은 자리에 코드 그림을 그린다(그림용 캔버스는 사진 뒤에 항상 있다).
- 상품 사진은 색별 배열(1번 앞, 2번 뒤). 사진이 있는 색을 고르면 사진, 없는 색을 고르면 재킷 렌더러. 기능 도해(섹션 3)는 호출선 좌표가 그림에 묶여 있으므로 **항상 코드 그림**이다.
- `alt` 기본값: 히어로 `한줌 다운을 입은 모델, {색 이름} 색상`, 룩북 `룩 {n}, {핏} {색 이름}`, 상품 `{상품명} {색 이름} {앞|뒤}`.

#### 3. 그림을 만드는 방법 (가장 중요. 클립아트처럼 보이면 실패다)

모든 그림은 두 개의 렌더러에서 나온다. 한 번 그린 결과는 `(종류, 색, 크기)` 키로 캐시한다. 난수는 전부 시드 고정(mulberry32)이라 새로고침해도 같은 그림이다.

**3.1 재킷 렌더러 `SRJ.jacket.render(canvas, opts)` (Canvas 2D)**

`opts = { model, color, view: 'front'|'back', pose: 'flat'|'worn', armAngle, light: {x, y}, parts: 'all'|['body','sleeveL',...], bg: 'none'|'studio', scale }`

- **설계 좌표계 1000×1200.** 윤곽은 SVG path 문자열 상수(Path2D)로 정의하고 부위별로 나눈다: `body`(몸판), `sleeveL`, `sleeveR`, `collar`(후드 또는 스탠드 칼라), `hem`(밑단 바인딩), `placket`(지퍼 덧단), `pocketL`, `pocketR`. 소매는 어깨점을 축으로 `armAngle`만큼 회전해 그린다(flat 18°, worn 6°~10°, 좌우를 2°쯤 다르게 해서 기계적인 대칭을 깬다).
- **모델 변형(파라미터):** `hood`(후드 있음/스탠드 칼라), `sleeves`(있음/없음=베스트), `length`(기본/크롭: 밑단을 110 올림), `fit`(공용: 일자 / 여성: 허리선에서 좌우 28씩 들어가고 밑단에서 다시 나옴). 상품 5종이 이 조합으로 만들어진다.
- **그리는 순서(부위마다 반복):**
  1. **명암 지도(회색조, 오프스크린).** 윤곽 안을 중간 회색 `#808080`으로 채운다. 그 위에 퀼팅 칸(배플)을 그린다. 몸판은 가로 칸 9줄(크롭 7줄), 소매는 소매 축에 수직인 칸 8줄. **칸의 경계선은 직선이 아니라 가운데가 14~22만큼 처지는 완만한 곡선**(물결 퀼팅. 가슴 쪽 3줄은 처짐이 크고 밑단으로 갈수록 평평해진다. 어깨 요크와 옆구리 패널에서는 칸 높이가 0.7배로 촘촘해진다: "나눈 패널"). 칸 하나는 볼록한 튜브처럼 칠한다: 세로 그라디언트로 위 12%는 박음선 그림자에서 올라오는 어둠, 25~40% 지점이 가장 밝고(하이라이트), 아래로 갈수록 어두워져 다음 박음선 직전 8%가 가장 어둡다. 박음선 자체는 1.5px 어두운 선 + 바로 아래 1px 밝은 선.
  2. **몸의 볼륨.** 전체에 가로 방향 원통 음영을 곱한다: 좌우 가장자리 14%가 어둡고 가운데보다 `light.x` 쪽으로 치우친 곳이 밝다. 소매도 축 기준으로 같은 음영. 겨드랑이, 소매와 몸판이 겹치는 곳, 칼라 아래에는 부드러운 접촉 그림자(방사형 그라디언트, 불투명도 0.35).
  3. **잔주름(사진처럼 보이게 하는 핵심).** 박음선마다 선을 따라 9~14px 간격으로 짧은 주름을 뿌린다: 박음선에서 수직으로 뻗는 길이 10~26px의 어두운 획과 그 옆 2px 떨어진 밝은 획 한 쌍, 불투명도 0.10~0.28, 방향과 길이를 시드 난수로 흔든다(다운 재킷 박음선의 오글오글한 당김). 팔꿈치 안쪽과 허리에는 더 긴 사선 주름 4~6개(길이 60~120, 폭 10의 부드러운 그라디언트 획).
  4. **광택.** 각 칸의 가장 밝은 띠 위에 폭이 불규칙한 흰색 반사 조각을 얹는다(칸마다 1~3조각, 길이 40~160, 높이 4~9, 양끝이 사라지는 그라디언트, `screen` 합성). 조각의 가로 위치는 `light.x`를 따라간다. 세기는 색마다 다르다(아래 표).
  5. **원단 결.** 6px 간격의 립스톱 격자(가로세로 0.5px 선, 불투명도 0.05) + 256px 노이즈 타일(`overlay`, 0.06). 둘 다 윤곽으로 자른다.
  6. **채색.** 색 캔버스 = 기본색 단색 → 명암 지도를 `multiply` → 광택 층을 `screen` → 색마다 정해진 그림자 틴트를 `soft-light`로 한 번. 마지막에 윤곽으로 `destination-in`. 가장자리에는 0.75px 어두운 안쪽 선(외곽선 스티커처럼 보이는 굵은 테두리 금지).
  7. **부속.** 지퍼: 덧단 가운데 세로선 + 3px 간격 이빨 점선 + 금속 풀러(작은 둥근 사각형, 하이라이트 한 점) + 풀러 끈(잔불 색 6×22 고리. **모든 색상에서 이 끈만 잔불**: 브랜드 표지). 손 주머니: 사선 지퍼 2개(길이 130, 덧단 그림자). 왼쪽 가슴: 12px 높이의 V선 심벌 자수(서리 백 또는 색에 따라 현무). 소매 끝: 6px 간격 세로 주름의 탄성 바인딩. 칼라 안쪽(앞에서 보이는 뒷목 안감): 기본색보다 35% 어둡게 + 고리 걸이 + 잔불 색 테이프 한 줄. 뒤(`view: 'back'`): 지퍼 없음, 어깨 요크 박음선, 밑단 조임 끈 2개, 뒷목 아래 작은 워드마크 `SEORIJAE` 전사.

- **색 바꾸기.** 명암 지도와 광택 층은 `(model, view, pose, size)`마다 한 번만 만들고, 색을 바꿀 때는 6번 채색만 다시 한다(8ms 이내). 화면에서는 이전 색 캔버스 위에 새 색을 180ms 교차 페이드하고, 동시에 `light.x`를 -0.3 → 0.3으로 훑어 **광택이 한 번 쓸고 지나가게** 한다(300ms, 광택 층만 다시 합성. reduced-motion에서는 교차 페이드만).
- **스튜디오 배경(`bg: 'studio'`, 상품 카드와 퀵뷰).** 세로 그라디언트 `#ECEEF0 → #D9DDE0` + 가운데가 밝은 방사형 조명(흰색 0.5) + 재킷 밑단 아래 타원 그림자 2겹(진하고 좁은 것 + 연하고 넓은 것, 축소 후 확대하는 방식의 블러). 재킷은 옷걸이 없이 떠 있는 "고스트 마네킹" 컷처럼 칼라 안쪽이 보인다. 재킷은 캔버스 높이의 78%, 살짝 오른쪽 위 조명.
- **해상도.** CSS 크기 × `min(devicePixelRatio, 2)`(휴대폰 1.5). 상품 카드 캔버스는 4:5. 블러는 `ctx.filter`에 의존하지 않는다(사파리 호환). 작은 캔버스에 그린 뒤 확대해 그리는 방식만 쓴다.
- **수납 주머니(스터프 색) `SRJ.jacket.renderPack(canvas, color)`:** 가로 190:세로 110 비율의 둥근 원통 꾸러미. 같은 채색 파이프라인에 잔주름을 3배로 뿌리고, 방사형으로 모이는 주름과 조임 끈, 고리. 도해와 히어로 패널 1장, 사은품 안내에 쓴다.

**3.2 장면 렌더러 `SRJ.scenes.render(canvas, sceneId, opts)` (Canvas 2D, 정지 화면)**

"사진"의 원칙: **얼굴을 그리지 않는다.** 모든 인물은 뒷모습, 후드를 쓴 옆뒷모습, 목 아래 크롭, 먼 거리의 작은 실루엣 중 하나다. 어색한 얼굴이 없으면 그림이 사진처럼 읽힌다. 인물의 상체는 **3.1의 재킷 렌더러(`pose: 'worn'`)를 그대로 합성**하므로 장면마다 재킷 색이 실제로 다르다.

- **공통 파이프라인(뒤에서 앞으로):**
  1. 하늘: 3~4단 세로 그라디언트(장면별 값) + 해 또는 달 주변 방사형 광(해는 화면 밖이나 능선 뒤에 두어 직접 보이지 않게).
  2. 능선 4~6겹: 겹마다 시드 1D 프랙탈 노이즈(4옥타브)로 윤곽 path를 만들고, 먼 겹일수록 하늘색에 가깝고 진폭이 작고 윤곽이 부드럽다(대기 원근). 겹과 겹 사이에 안개 띠(가로로 긴 타원 그라디언트 여러 장, 불투명도 0.15~0.4). 가까운 2겹에는 눈 덮인 사면의 결(능선 법선 방향의 짧은 밝은 획)과 바위 얼룩, 침엽수 실루엣 띠(작은 삼각 톱니 묶음).
  3. **심도.** 먼 겹은 1/4 크기 오프스크린에 그렸다가 확대해 흐리게, 인물이 선 겹은 원래 해상도로 선명하게. 맨 앞에 화면을 스치는 흐린 눈발이나 풀 실루엣(크게, 아주 흐리게) 한두 개로 전경 흐림.
  4. 인물: 다리(짙은 바지, 걷는 자세의 path 2개), 등산화, 장갑, 머리(후드 또는 비니의 단순한 덩어리, 얼굴 없음), 필요하면 배낭(뒷모습 컷) + 재킷 합성. 해가 있는 쪽 가장자리에 **림 라이트**(인물 윤곽을 2px 바깥으로 넓힌 마스크에 하늘 광색을 `screen`, 반대쪽은 `multiply`로 12% 어둡게). 발밑에서 해 반대쪽으로 길게 눕는 그림자(눈 위, 청보라, 불투명도 0.35, 끝으로 갈수록 흐림). 발 주변에 눈이 패인 자국.
  5. 눈발: 크기 1~5px 점 120~300개, 바람 방향으로 3~9px 늘인 타원, 큰 것일수록 흐리게.
  6. **색 보정과 필름 질감.** 전체에 그림자=청록(`#0E2A33` soft-light 0.25), 밝은 곳=주황(`#FF8A4A` soft-light 0.12, 화면 위쪽 절반에만) 그라디언트 맵. 네 귀퉁이 비네트(0.35). 노이즈 타일 그레인(overlay 0.08). 이 마지막 단계가 "코드 그림"을 "사진"으로 바꾼다. 생략 금지.
- **장면 목록(히어로 5, 룩북 10, 전면 1 = 16장. 시드, 구도, 재킷 색 고정):**

- **JS가 꺼졌을 때.** 캔버스 자리마다 하늘 그라디언트 CSS 배경 + inline SVG `<symbol id="jk">`(단순한 재킷 윤곽 + 곡선 박음선 8줄) `<use>`가 보인다. 상품 카드도 같은 심벌을 스튜디오 회색 면 위에 색만 바꿔 보여준다.

#### 4. 페이지 구조와 문구

위에서 아래 순서. 높이 감각(1440 기준 전체 약 6,000px): 프로모 36 / 헤더 64 / 서브 탭 48 / 히어로 752(첫 화면 900 안에 띠 아랫부분까지) / 도해 900(pin 포함 스크롤 250vh) / 큰 글자 520 / 룩북 980 + 아코디언 / 전면 컷 810 / 상품 880 / 안내 320 / 푸터 420.

**4.0 프로모 바 (`role="region" aria-label="혜택 안내"`)**
- 현무 배경, 아래 1px 능선 회 선, 높이 36px(모바일 44px, 문구 두 줄 허용). 가운데: `카카오톡 채널을 추가하면 첫 구매 7,000원 쿠폰을 드립니다` + 밑줄 텍스트 버튼 `쿠폰 받기`. 오른쪽 끝: 닫기 버튼(X 아이콘, `aria-label="혜택 안내 닫기"`, 44px 터치 영역).
- `쿠폰 받기`: 문구가 그 자리에서 `쿠폰을 담았습니다. 장바구니에서 자동으로 적용됩니다.`로 바뀌고(150ms 교차), 장바구니에 `HANJUM7` 쿠폰이 들어간다(10만 원 이상일 때 7,000원 할인). 실제 메신저로 이동하지 않는다. 카카오의 로고, 말풍선 심벌, 노란 브랜드색은 쓰지 않는다(글자로만 언급).
- 닫기: 바가 `grid-template-rows 1fr → 0fr`로 220ms에 접히고 세션 동안 다시 나오지 않는다. 받은 쿠폰은 유지된다.

**4.1 헤더 (흰색, 스크롤하면 지나간다. 고정 아님)**
- 종이 백 배경, 먹 글자, 높이 64px. 왼쪽: 브랜드 로고(`#top`). 가운데 내비(IBM Plex Sans KR 500, 15px): `공용` `여성` `룩북` `소재` `배송·교환`. `공용`과 `여성`은 `#products`로 가면서 상품 필터를 그 값으로 바꾼다. `룩북` → `#look`, `소재` → `#tech`, `배송·교환` → `#guide`. (가운뎃점은 이 메뉴 이름 하나에만 쓴다.)
- 오른쪽 아이콘 버튼 3개(1.5px 선 아이콘, 직접 그린 SVG, 44px): 검색(`aria-label="상품 검색"`), 찜(`aria-label="찜한 상품 0개"`, 하트), 장바구니(`aria-label="장바구니 0개"`, 개수 배지는 잔불 원에 현무 숫자).

**4.2 서브 탭 (`<nav aria-label="기획전 탐색">`, `position: sticky; top: 0`)**

- **붙은 뒤의 변화:** 헤더가 화면 밖으로 나가 탭이 맨 위에 붙으면(IntersectionObserver로 헤더 감시) 탭 오른쪽에 작은 찜, 장바구니 버튼과 개수가 페이드로 나타난다(180ms). 흰 헤더가 사라진 뒤에도 장바구니에 닿을 수 있어야 한다. 가운데에는 얇은 진행선(탭 밑줄과 같은 높이, 능선 회 위에 서리 백 30%, 페이지 진행률 scaleX)을 둔다.
- 모바일: 탭 2개가 반씩. 오른쪽 버튼은 붙은 뒤에만 나타나며 그때 탭 글자는 자간을 0.08em으로 줄인다.

#### 5. 시그니처 효과 4막 ("접힘 → 부풂")

공통: 전부 `gsap.matchMedia()` 안에서 `(prefers-reduced-motion: no-preference)` / `reduce`, `(min-width: 768px)`, `(hover: hover) and (pointer: fine)`로 분기. 숨김 시작 상태는 JS가 만든다. `?shot=1`은 reduced-motion과 같은 정지 상태에 아래 지정 프레임을 더한 것.

**5.1 모델 띠 (첫 화면의 시그니처. Draggable + InertiaPlugin)**
- 구성: 패널 5장(`h1`~`h5`). 패널 비율 4:5, 높이 `clamp(340px, 52svh, 560px)`, 패널 사이 8px. 데스크톱에서는 3.4장이 보인다. 띠는 화면 좌우 끝까지 가고(전체 폭), 양끝 패널이 잘려 보여 "더 있다"를 알린다. 무한 순환(패널을 앞뒤로 복제하고 `gsap.utils.wrap`으로 x를 감는다. 복제본은 `aria-hidden`, `inert`).
- 패널 안: 장면 캔버스(패널보다 14% 넓게 그려 두고 드래그 방향 반대로 미끄러지는 **안쪽 시차**), 왼쪽 아래 색 라벨(Archivo 600 wdth 62, 자간 0.2em, 12px: `EMBER` + 한글 13px `잔불`), 오른쪽 아래 텍스트 버튼 `이 색상 보기`(그 장면의 상품과 색으로 퀵뷰. `h5`는 `수납 방법 보기`로 `#tech`로 이동).
- **로드 연출(1.1초 이내, 접힘 → 부풂):** 패널 5장이 화면 가운데에 **폭 18%로 눌린 채 붙어 있다가**(`clip-path: inset(0 41% 0 41%)` + x를 가운데로 모음) 0.9초에 걸쳐 제 폭으로 펴지며 제자리로 벌어진다(`power3.out`, 패널별 40ms 차이). 동시에 로고타입 1행의 `wdth`가 62 → 125로 넓어진다(0.9초). h1, 본문, 버튼은 처음부터 보인다(움직이지 않음). 패널은 눌린 상태에서도 가운데 띠가 보이므로 빈 화면이 없다.
- **자동 넘김:** 4.5초마다 한 장씩 왼쪽으로(0.9초, `power2.inOut`). 포인터가 띠 위에 있거나, 포커스가 띠 안에 있거나, 띠가 화면 밖이거나, 탭이 숨겨지면 멈춘다. 멈춤/재생 버튼(`aria-pressed`, `aria-label="자동 넘김 멈춤"`)으로 사용자가 끌 수 있고, 한 번 드래그하면 자동 넘김은 꺼진다. 진행 표시는 `2 / 5` 숫자와 그 옆 24px 선이 4.5초 동안 차오르는 것.
- **드래그:** `Draggable.create(proxy, { type: 'x', inertia: true, snap: 패널 폭 + 간격 })`. 누르는 즉시 커서 `grabbing`, 드래그 중 패널들이 속도에 비례해 최대 `skewX(2deg)`. 10px 미만 이동은 클릭으로 처리해 패널 안 버튼이 눌린다. 세로 스크롤을 막지 않는다(`touch-action: pan-y`).
- **키보드:** 띠는 `role="group" aria-roledescription="캐러셀" aria-label="한줌 다운 착용 사진"`. 이전/다음 버튼, 띠에 포커스가 있을 때 좌우 화살표. 현재 패널이 바뀌면 숫자 표시가 라이브 영역으로 읽힌다(자동 넘김 중에는 `aria-live="off"`).
- **모바일(390):** 패널 폭 72vw, 높이 `min(96vw, 52svh)`, 1.3장 보임. 손가락 스와이프(같은 Draggable). 로드 연출은 같지만 3장만 참여. 안쪽 시차 8%. 컨트롤 줄은 숫자와 멈춤 버튼만(이전/다음은 스와이프로 대체하되 스크린리더용으로 DOM에는 남기고 시각적으로도 44px 유지: 띠 아래 오른쪽).
- **reduced-motion:** 로드 연출 없음, 자동 넘김 꺼짐(버튼은 `재생` 상태로 표시하되 눌러도 0.01초 전환), 드래그와 버튼은 즉시 이동(교차 150ms). 기본 가로 스냅 스크롤(`scroll-snap-type: x mandatory`)로 대체해도 된다.
- **`?shot=1`:** 연출 생략. `h1`(잔불, 능선 뒷모습)이 왼쪽에서 두 번째 자리, 왼쪽 끝에 `h5`가 반쯤 잘려 보이고 오른쪽으로 `h2`, `h3`가 이어지는 정지 화면. 로고타입 wdth 125. 프로모 바는 열린 상태. 보이는 4장을 동기 렌더한 뒤에 `document.documentElement.classList.add('is-ready')`.

**5.2 기능 도해: 스스로 그려지는 호출선 + 층으로 벌어지는 재킷 (ScrollTrigger pin + DrawSVG)**
- 구조: 무대 `div`(비율 16:10, 최대 폭 1280) 안에 재킷을 **부위별 캔버스 6장**으로 겹쳐 놓는다(`parts`로 따로 렌더: 몸판, 왼소매, 오른소매, 후드, 왼쪽 가슴의 절개 창, 수납 주머니). 그 위에 같은 좌표계의 `<svg viewBox="0 0 1600 1000" aria-hidden="true">`: 호출선 5개(`<path>`, 1px 서리 백, 재킷 위 지점에서 수평 → 45° 꺾임 → 수평으로 라벨까지 가는 3마디 선), 시작점의 `+` 마커(12px 십자, 잔불), 라벨 쪽 끝의 2px 점. 라벨 글은 SVG가 아니라 HTML로 무대 위에 절대 배치한다(읽기와 줄바꿈 때문). 호출 목록은 DOM 순서상 `<ol>`이라 스크린리더는 다섯 항목을 차례로 읽는다.
- **절개 창:** 밑단 왼쪽에 140×140의 둥근 사각형 창. 창 안에는 세 층이 비스듬히 어긋나 보인다: 겉감(잔불, 립스톱 격자가 확대되어 보임) / 솜털(흰 솜털 클러스터 60~80개: 중심에서 방사형으로 뻗는 가는 곡선 12~18가닥씩, 서로 겹침, 가장자리에 물방울 3~4개가 맺혀 구르는 모습) / 안감(짙은 회색). Canvas로 그린다.
- **데스크톱 타임라인(섹션 pin, 스크롤 길이 250vh, `scrub: 0.6`):**
  - 0~8%: 제목이 보인 채 재킷이 조립된 상태로 서 있고, 빛이 왼쪽에서 오른쪽으로 한 번 쓸고 지나간다(`light.x` -0.4 → 0.4. 광택 층만 재합성. 이것이 "재킷이 도는" 인상을 준다. 실제 3D 회전은 하지 않는다).
  - 8~30%: 호출 1(수납) 선이 그려지고(DrawSVG `0% → 100%`), 선이 끝에 닿는 순간 `+` 마커가 `scale .9 → 1`, 라벨이 `opacity 0 → 1, y 8 → 0`. 수납 주머니 그림이 재킷 주머니 위치에서 라벨 옆으로 나온다.
  - 30~48%: 호출 2(물결 퀼팅). 재킷 위 박음선 3줄을 따라 잔불색 선이 한 번 지나간다(SVG path, DrawSVG로 `0% 12%` 구간이 이동).
  - 48~70%: **벌어짐.** 왼소매 `x -64, rotate -4°`, 오른소매 `x 64, rotate 4°`, 후드 `y -52`, 몸판 `scale 0.98`. 어깨 요크와 옆구리 패널 윤곽에 1px 서리 백 점선이 나타난다. 호출 3(나눈 패널)과 4(겉감) 선이 그려진다. 호출선의 시작점은 부위와 함께 움직인다(선을 부위 그룹에 넣지 말고, 벌어진 뒤의 좌표로 그려 두고 이 구간에서만 나타나게 한다).
  - 70~88%: 절개 창이 열린다(`clip-path: inset(50%) → inset(0)`), 세 층이 12px씩 어긋나며 벌어지고, 호출 5(솜털) 선. 스펙 칩의 숫자 `90/10`, `850`이 0에서 올라온다(0.6초, 스크럽이 아니라 한 번 재생).
  - 88~100%: 부위가 다시 모이고(조립 상태), 아이콘 행 4개가 80ms 간격으로 나타난다. pin 해제.
  - 뒤로 스크롤하면 그대로 되감긴다. pin 중 오른쪽 가장자리에 5칸 진행 표시(세로 점 5개, 현재 호출이 잔불).
- **모바일(390, pin 없음):** 재킷(폭 78vw)이 위, 호출은 그 아래 **번호 없는 5줄 목록**(각 줄: `+` 마커와 라틴 명칭, 한글 이름, 설명. 줄 사이 1px 선). 재킷 위에 `+` 마커 5개가 버튼으로 놓이고(44px 터치 영역), 누르면 해당 목록 줄로 부드럽게 스크롤하고 그 줄 배경이 흑연으로 1.2초 밝아진다. 반대로 목록 줄이 화면 가운데에 오면 재킷 위 그 마커가 잔불로 채워진다(IntersectionObserver). 재킷은 목록을 읽는 동안 `position: sticky; top: 56px`로 화면 위쪽 42svh 안에 남는다. 벌어짐 연출은 "나눈 패널" 줄이 가운데 왔을 때 한 번(0.6초, 이동 폭 절반), 절개 창은 "젖지 않는 솜털" 줄에서 열린다. 세로 호출선은 마커에서 아래로 24px만 그려지는 짧은 선(DrawSVG, 한 번).
- **reduced-motion / `?shot=1`:** pin 없음. 조립된 재킷 + 호출선 5개와 라벨이 전부 그려진 완성 도해 + 절개 창 열림 + 칩 최종값. 한 화면에 다 보인다.
- **JS 없음:** `<symbol>` 재킷 + `<ol>` 다섯 항목이 2열로 보인다.

**5.3 큰 제품명: 폭이 부푸는 글자 (ScrollTrigger scrub)**
- 세 단어를 각각 `<span>`으로. 글자 크기는 **`wdth 125`일 때 한 줄이 내부 폭(좌우 여백 제외)을 정확히 채우도록** JS가 측정해 정한다(폰트 로드 후, 리사이즈 150ms 디바운스. 임시로 125로 놓고 `scrollWidth`를 재서 비례 계산. 대략 1440에서 13.5vw).
- 스크럽(섹션 윗변이 화면 아래 90%에 닿을 때부터 화면 가운데 40%에 올 때까지, `scrub: 0.5`): `font-variation-settings "wdth"` **62 → 125**, `wght` 800 → 620, 단어 사이 간격 0.02em → 0.28em. 시작에서는 세 단어가 가운데에 좁고 굵게 뭉쳐 있고(접힌 한 줌), 끝에서는 화면 양끝까지 펴진다(부푼 한 벌). 글자 높이는 변하지 않으므로 레이아웃 이동이 없다.
- 동시에 글자 안쪽을 흐르는 질감: 글자에 `background-clip: text`로 서리 백 단색 위에 아주 옅은 가로 박음선 무늬(1px 선, 14px 간격, 현무 12%)를 깔아, 가까이서 보면 글자가 퀼팅된 것처럼 보인다. 끝 지점(125)에서 마지막 단어 `DOWN`의 아래 가장자리에 잔불색 2px 선이 왼쪽에서 오른쪽으로 그어진다(scaleX).
- 좌우 작은 글 `접으면 한 줌` / `펼치면 한 벌`: 진행 0~0.3에서 왼쪽이 서리 백, 0.7~1에서 오른쪽이 서리 백(나머지는 능선 회보다 밝은 안개 40%. 대비를 위해 최소 `#7C838A`).
- **모바일:** 세 단어를 **한 줄에 하나씩 세 줄로** 쌓는다. 줄마다 `wdth 125`에서 폭을 채우는 크기를 따로 계산(`DOWN`이 가장 큼. 줄 높이 0.86). 같은 62 → 125 스크럽을 줄마다 0.12씩 늦게. 섹션 높이는 세 줄 합계로 고정.
- **가변 폭 미지원 대체:** `CSS.supports('font-variation-settings', '"wdth" 100')`이 거짓이면 `scaleX 0.55 → 1`(`transform-origin: center`) + `letter-spacing`으로 같은 인상을 낸다.
- **reduced-motion / `?shot=1`:** `wdth 125`, 펼친 상태로 고정. 잔불 선 그어진 상태.

**5.4 원통형 룩북 (CSS 3D + Draggable + InertiaPlugin)**
- 구조: `.ring`(`transform-style: preserve-3d`) 안에 카드 10장. 카드 `300×440`(데스크톱), 각 카드 `rotateY(i × 36deg) translateZ(R)`, `R = 카드폭/2 ÷ tan(18°) + 34` ≈ 496px. 무대 `perspective: 1500px`, `perspective-origin: 50% 42%`, 무대 높이 620px, `overflow: clip`. 원통을 **바깥에서** 본다: 앞 카드가 정면, 좌우 두 장씩이 비스듬히 뒤로 물러나고, 뒤쪽 카드는 `backface-visibility: hidden`으로 숨긴다. 링 전체를 `rotateX(-4deg)`로 살짝 숙여 윗면이 보이는 느낌을 준다.
- 깊이 표현: 회전값이 바뀔 때마다(`onUpdate`, rAF 한 번) 카드별 정면 각도 차이 `d`로 밝기를 정한다. 카드 위 현무 덮개의 불투명도 `min(0.72, |d| / 110)`, 앞 카드만 0. 앞 카드 아래에는 바닥 반사(카드의 `scaleY(-1)` 복제 대신, 바닥에 깔린 가로 타원 그라디언트 그림자 하나)만 둔다. 카드 모서리 반경 2px, 테두리 없음.
- 카드 내용: 룩북 장면 캔버스(3:4.4) + 왼쪽 아래 `LOOK 03`(Archivo 600 wdth 62, 12px, 자간 0.2em). 카드 자체는 포커스 대상이 아니고(뒤쪽 카드에 포커스가 가면 안 됨), 조작은 아래 컨트롤로 한다.
- **조작:**
  - 드래그: 무대 위 투명 프록시에 `Draggable({ type: 'x', inertia: true })`. 드래그 1px = 0.28°. 놓으면 관성으로 돌다가 36° 단위로 스냅(`snap` 함수, `InertiaPlugin`). 빠르게 던지면 여러 장을 지나간다. `touch-action: pan-y`.
  - 버튼: 이전/다음(무대 좌우 아래, 44px, 1px 서리 백 30% 테두리의 정사각형), 측면 라벨 버튼(공용 핏 = 0번 카드로, 여성 핏 = 5번 카드로. 가까운 방향으로 0.9초 `power3.inOut`).
  - 키보드: 무대는 `tabindex="0" role="group" aria-roledescription="캐러셀" aria-label="룩북, 10장"`. 좌우 화살표 = 한 장, Home/End = 공용 첫 장/여성 첫 장. 바뀔 때마다 캡션 줄(`aria-live="polite"`)이 `룩 6 / 10, 여성 핏, 서리 색상`을 읽는다.
  - 대기 회전: 화면에 들어오면 6초에 한 장 속도(6°/초)로 천천히 돈다. 포인터 진입, 포커스, 드래그, 버튼 조작 시 멈추고 **다시 시작하지 않는다.** 캡션 줄 옆에 멈춤/재생 버튼. 화면 밖과 탭 비활성 시 정지. 대기 회전 중에는 라이브 영역을 끈다.
  - 앞 카드를 클릭(드래그 아님)하거나 `이 옷 보기`를 누르면 그 룩의 상품과 색으로 퀵뷰.
- **입장(한 번):** 섹션이 들어올 때 링이 `rotateY -50° → 0°`, `scale 0.92 → 1`로 0.9초에 자리를 잡는다. 이 섹션의 유일한 입장 연출.
- **모바일(390):** 카드 `200×294`, `R ≈ 340`, `perspective 900px`, 무대 높이 400px. 앞 카드 + 좌우 한 장씩의 가장자리가 보인다. 스와이프로 회전, 측면 세로 라벨 대신 무대 위에 세그먼트 2칸 `공용 핏` / `여성 핏`. 이전/다음 버튼은 캡션 줄 양옆.
- **reduced-motion:** 3D 원통을 쓰지 않는다. 같은 카드 10장이 가로 스냅 스크롤 목록(`scroll-snap-type: x mandatory`, 카드 폭 데스크톱 300 / 모바일 70vw)으로 보이고, 이전/다음 버튼은 `scrollBy`. 측면 라벨은 해당 카드로 스크롤. 
- **`?shot=1`:** 원통, 0번 카드 정면에서 -8° 돌아간 정지 상태(대기 회전 없음).
- **JS 없음 / `transform-style: preserve-3d` 미지원:** 가로 스크롤 목록(위 reduced-motion과 같은 CSS가 기본이고, JS가 `html.js.has-3d`일 때만 원통으로 바꾼다).

**5.5 퀵뷰: 카드에서 펼쳐지는 시트 (Flip)**

#### 6. 쇼핑 동작 (전부 화면 안에서만 동작하는 데모)

- **상태:** `state = { cart: [{ id, color, size, qty }], wish: [id...], coupon: null|'HANJUM7', promoClosed: bool, filter }`. 바뀔 때마다 `sessionStorage['seorijae:v1']`에 저장하고 로드할 때 복원한다. **반드시 `try/catch`**(저장소가 막힌 환경에서는 메모리 상태로만 동작. 오류를 콘솔에 남기지 않는다). `?shot=1`에서는 복원하지 않는다(항상 빈 장바구니, 프로모 열림).
- **찜:** 카드, 퀵뷰, 서랍 어디서 눌러도 같은 상품의 모든 하트가 동기화된다. 켤 때 하트 `scale 1 → 1.18 → 1`(220ms), 헤더와 서브 탭의 찜 개수 갱신, 알림 `찜한 상품에 담았습니다`. 세션 동안 유지.
- **장바구니 담기:** 퀵뷰의 재킷 축소본(48px)이 장바구니 아이콘(헤더가 보이면 헤더, 아니면 서브 탭의 아이콘)으로 0.5초에 날아가고(`power2.in`, 살짝 포물선), 개수 배지가 `scale 1 → 1.25 → 1`. 버튼 문구가 1.6초 동안 `담았습니다`로 바뀐다. 퀵뷰는 닫지 않는다. 하단 알림(토스트, `role="status"`, 화면 아래 가운데. 모바일에서는 컨셉 배지 위): `장바구니에 담았습니다` + 텍스트 버튼 `장바구니 보기`. 같은 옵션을 다시 담으면 수량이 합쳐진다(최대 5).
- **서랍(오른쪽에서, 폭 440px / 모바일 100vw, 흑연 배경. `<dialog>` 또는 `role="dialog" aria-modal`):** 위에 탭 2개 `장바구니 2` / `찜 3`(`role="tablist"`). 닫기 버튼, Esc, 배경 클릭으로 닫힘, 닫으면 연 버튼으로 포커스 복귀. 열림 `x 100% → 0` 0.34초, 닫힘 0.24초.
  - **진행 막대(서랍 맨 위):** 눈금 2개가 있는 한 줄 막대(높이 4px, 능선 회 바탕에 잔불이 `scaleX`로 차오름, 360ms). 눈금 1 `7만 원 무료 배송`, 눈금 2 `60만 원 수납 색 증정`. 막대 위 문구(`aria-live="polite"`): 7만 미만 `41,000원만 더 담으면 배송비가 무료입니다` / 7만 이상 60만 미만 `무료로 보내 드립니다. 202,000원을 더 담으면 압축 수납 색을 드립니다` / 60만 이상 `무료 배송에 압축 수납 색까지 함께 보냅니다`. 눈금을 넘는 순간 눈금 표시가 잔불로 채워진다(체크 표시 그리기 200ms).

#### 7. 보조 모션과 상태(조용하게)

- 버튼 누름 `scale(0.97)` 120ms. 호버는 fine pointer에서만: 주 버튼 배경이 10% 밝아짐, 텍스트 버튼 밑줄이 왼쪽에서 그어짐(180ms).
- 포커스 링: 다크 면에서는 `2px solid #FF6A2B`, 흰 면에서는 `2px solid #111315`, `outline-offset: 2px`.
- 스크롤 입장 연출은 **5.2, 5.3, 5.4의 것만.** 상품 카드, 안내, 푸터에는 입장 애니메이션이 없다.
- 전면 컷의 6% 시차(데스크톱만).
- 무한히 까딱거리는 장식 금지. 자동으로 움직이는 것은 모델 띠와 룩북 대기 회전 둘뿐이고 둘 다 멈춤 버튼이 있으며 화면 밖에서 멈춘다.
- 스크립트 진입부 `try/catch` → 실패 시 `html.no-motion`. GSAP이 없으면: 띠와 룩북은 가로 스냅 스크롤, 도해는 완성 상태, 큰 글자는 `wdth 125`, 퀵뷰와 서랍은 연출 없이 열림(쇼핑 동작은 GSAP 없이도 돌아가야 한다: 상태와 DOM 갱신 코드는 GSAP에 의존하지 않게 분리).

#### 9. 접근성 메모(4.5에 더해)

- 제목 구조: h1 `한 줌으로 접히는 겨울` → h2 도해 / h2 룩북 / h2 전면 컷(시각적으로 숨김: `해 질 녘 능선의 한줌 다운`) / h2 상품 → 카드 h3 / h2 구매 안내 → h3 3개 / 푸터.
- 캔버스는 기본 `aria-hidden="true"`. 단 상품 카드와 퀵뷰의 재킷, 히어로 패널, 룩북 카드는 `role="img"` + 2절의 `alt` 규칙과 같은 `aria-label`.
- 색 이름은 색만으로 전달하지 않는다(스와치마다 이름 텍스트 또는 `aria-label`, 선택된 색 이름을 글로 표시).
- 다크 면의 본문은 서리 백 또는 안개만. 잔불 글자는 12px 이상 600 굵기 이상의 라벨과 숫자에만. 사진 위 글자는 스크림 위에서 4.5:1 확인.
- 드래그 전용 동작 없음(띠, 원통, 시트 닫기 모두 버튼과 키보드 대안).
- 라틴 라벨은 장식이 아니라 명칭이므로 읽히게 두되, 바로 옆 한글 이름과 중복되는 곳(호출 라벨)은 라틴 쪽에 `lang="en"`을 준다.

#### 10. 성능 메모

- 애니메이션 루프가 없는 페이지다. 캔버스는 한 번 그리고 끝. rAF를 쓰는 곳은 드래그 중 갱신, 퀵뷰 광택 추적(30fps 제한), 도해의 빛 훑기뿐이며 끝나면 멈춘다.
- 캔버스 메모리: 장면 16장 + 상품 렌더 캐시. 휴대폰에서는 장면을 CSS 크기 × 1.5로, 룩북 카드는 화면 근처 5장만 원해상도로 그리고 나머지는 1/2 해상도(앞에 오면 다시 그림). 캐시 상한 40장(오래된 것부터 버림).
- 명암 지도와 장면의 무거운 단계는 `requestIdleCallback`(없으면 `setTimeout`)으로 프레임당 하나씩. 첫 화면 차단 시간 합계 150ms 이하.
- 폰트 로드 후(`document.fonts.ready` 또는 800ms) 큰 글자 크기 재측정과 `ScrollTrigger.refresh()`.
- pin은 도해 한 곳(250vh)뿐.

#### 11. `?shot=1` 정지 장면(썸네일)

1440×900: 프로모 바(열림) + 흰 헤더 + 서브 탭(`HANJUM 26W` 활성, 잔불 밑줄) + 가운데 로고타입(그라디언트, wdth 125) + h1 + 본문 + 잔불 버튼 + 그 아래 모델 띠 윗부분(잔불 능선 컷이 왼쪽에서 두 번째). 인트로 생략, 자동 넘김 정지, 세션 복원 안 함, 컨셉 배지 숨김(공유 스크립트가 처리). 검은 바탕 위에 주황 재킷 한 벌과 주황 버튼 하나만 색을 갖는 화면이어야 한다.

#### 12. 이미지 계획 요약

전부 코드. 히어로 띠 5장과 룩북 10장과 전면 컷 1장 = 장면 렌더러(Canvas 2D, 재킷 렌더러 합성). 도해 = 재킷 렌더러(부위별) + SVG 호출선 + Canvas 절개 창. 상품 카드와 퀵뷰와 서랍 축소본 = 재킷 렌더러(스튜디오 배경, 5모델 × 색 × 앞뒤). 아이콘(검색, 하트, 장바구니, 닫기, 스테퍼, 기능 아이콘 4, 소품 3) = 1.5px 선 inline SVG, 직접 그림. JS 없음 대체 = `<symbol>` 재킷 + CSS 그라디언트. 외부 이미지 0장. 실제 사진은 `PHOTOS`에 경로를 넣었을 때만.

#### 13. 완료 기준에 더하는 항목 (PLAN 4.8 + BUILD-CONTRACT에 추가)

1. 재킷 렌더를 600px 폭으로 캡처해 직접 본다. 칸마다 볼록함, 박음선의 잔주름, 광택 조각이 보이고 "평평한 색면 + 줄무늬"로 보이지 않아야 한다. 현무색에서 광택이, 서리색에서 그림자가 읽히는지 따로 확인.
2. 장면 3장 이상(`h1`, `h3`, `full`)을 캡처해 본다. 능선 겹의 원근, 림 라이트, 그레인이 있고 인물이 종이 인형처럼 보이지 않아야 한다. 얼굴이 그려진 장면이 없어야 한다.
3. 쇼핑 흐름을 실제로 눌러 본다: 색 바꾸기 → 사이즈 → 담기 → 서랍에서 수량 +/− → 진행 막대와 총액 변화 → 쿠폰 받기 후 할인 줄 → 주문하기의 고지 문구. 품절 사이즈가 선택되지 않는지, 새로고침 뒤 장바구니와 찜이 남는지.
4. 프로모 바를 닫고 새로고침해도 닫힌 채인지. 서브 탭이 `#products`에서 `PRODUCTS`로 바뀌는지.
5. `PHOTOS`가 비었을 때 `./photos/` 요청이 0건인지. 시험 삼아 없는 경로 하나를 넣었을 때 그 슬롯만 코드 그림으로 되돌아오는지 확인하고, **확인 후 다시 비운다.**
6. 390px에서 원통, 띠, 큰 글자가 가로 스크롤을 만들지 않는지(report.json overflow 0).
7. 레퍼런스 브랜드의 이름, 제품명, 문구, 기능 명칭이 페이지 어디에도 없는지 검색으로 확인. 시안색 포인트가 없는지.
8. `컨셉 시안이라 실제로 주문되지 않습니다.`가 퀵뷰 버튼 아래, 상품 섹션 끝, 주문 요약 세 곳에 있는지. 푸터의 사업자 정보가 전부 `000`, `OO`, `홍길동`, `.example` 같은 명백한 가상 값인지.

- **중요 스킬:** frontend-design(절제된 다크, 라벨 남용 금지), gsap-plugins(Draggable, Inertia, Flip, DrawSVG), gsap-scrolltrigger, better-motion, emil-design-eng(시트, 서랍, 스테퍼의 손맛), apple-design(관성, 시트 드래그), adapt, accessibility, better-writing(쇼핑 문구).
